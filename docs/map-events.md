# 天城地图 · 事件联动

地图不只是地图，是天城的综合看板。剧情里的通报、快讯、执法公告写到的火灾、盗窃、封锁、停电，都会落到地图上对应的位置。遇到网络攻击，地图本身会跟着花屏。

思路来自现实里的校园安全警报、犯罪地图和火情地图：一条通报对应地图上一个点。

- 视觉样例和给模型看的写法在《天城视觉规范》的「城市地图 · 事件联动」一节。
- 世界书里对应的条目是「地图联动规范」「视觉样例·安全通报 · 地图标记」「视觉样例·信号干扰」。

## 链路

```
模型输出的载体（通报 / 快讯 …）
  └─ 末尾一个隐藏标签 <span style="display:none" data-tcmap="…">
       └─ 卡内脚本 map/tavern/eden-map.js 扫描最近 200 楼（切楼、收到、编辑、重 roll、删楼时重扫，400 ms 防抖）
            ├─ 悬浮按钮角标：80 楼内未解除的事件数
            └─ postMessage {type:'eden-map:events', list, last} → 查看器 map/viewer.html
                 └─ map/events.js（TCEvents）
                      ├─ 地点解析 → 事件点叠加层、世界图「天城」角标、「事件 N」开关
                      └─ 网络攻击 → body[data-glitch=1|2|3] 花屏
```

事件每次都从聊天记录重新推导，不单独存储。所以重 roll、删楼、改楼之后，地图会自动和聊天保持一致。

## 标签格式

```html
<span style="display:none" data-tcmap="类型=火灾;地点=7号井黑市;标题=仓库起火;等级=3;状态=发生中;时间=2088.01.12 21:40;编号=LEB-88-0317"></span>
```

字段之间用 `;` 或 `；` 分隔，字段名和值之间用 `=` 或 `＝`。

| 字段 | 必填 | 说明 |
|---|---|---|
| 类型 | 是 | 写具体类型（v2：9 大类 66 种，见下方「事件体系 v2」）。近义词也能识别（`events.mjs` 的 `ALIAS_CAT`，包含关系取最长）；只写大类名（「人物」「治安」）时记「其他」但按该大类配色；认不出的记「其他」 |
| 地点 | 是 | 地标名或别名（与 `maps.json` 的 `name` / `alias` 做最长匹配），或者层名（上层、中层、下层、地基区、7 号井 …） |
| 标题 | 是 | 十个字以内 |
| 等级 | 否 | 1–3，默认 2 |
| 状态 | 否 | 含「解除 / 结束 / 恢复 / 已控制 / 扑灭」的算已解除；含「处置 / 处理 / 调查 / 进行」的算处置中；其余算发生中 |
| 时间 | 否 | 剧情内时间，只用于显示 |
| 编号 | 否 | 去重键。没有编号时用「类型 + 地点 + 标题」。同一个键后出现的标签会覆盖前面的，用来更新状态 |
| 范围 | 网络攻击 | 全城、某一层或某个地标，默认取地点 |
| 持续 | 网络攻击 | 从所在楼起影响多少楼，默认 3 |
| 坐标、层 | 否 | `坐标=0.42,0.63`（底图归一化坐标）加 `层=中层`，直接定位，跳过地点解析 |

### 地点解析

1. 有 `坐标`：直接使用。
2. 地点文字包含某个地标的名称或别名：钉在该地标上。多个都能匹配时取最长的那个。地标可以在任意一层，事件就归到那一层。
3. 只匹配到层名：落在该层中部，位置由地点文字的哈希决定（同一地点每次都在同一处），并画一圈虚线，地点卡里写「位置不详」。
4. 什么都没匹配到：归到中层，处理方法同第 3 条。

### 显示规则

- 只画当前地图上、80 楼以内的事件。数据源的事件不受楼数限制。
- 同一位置有多个事件时，依次错开摆放。
- 发生中的事件会脉动，3 级更大、更快。处置中停止脉动。已解除变成半透明灰色。
- 世界图上，「天城」标签右上角显示未解除事件的数量。
- 点击事件点会弹出地点卡：类型 · 标题、地点、状态、时间、来源。

### 花屏

网络攻击事件在以下条件下触发花屏：

- 状态未解除；
- 当前最新楼号 ≤ 所在楼 + 持续楼数；
- 范围命中「全城」、当前地图，或当前层的层名。

取所有生效事件里等级最高的一个作为花屏档位：

| 档位 | 效果 |
|---|---|
| 1 | 色散 |
| 2 | 色散 + 横向撕裂 |
| 3 | 色散 + 横向撕裂 + 马赛克块 |

花屏全部用 CSS 实现（`body[data-glitch]`），不改变底图，不增加网络请求。

## 独立数据源（feeds）

在 `map/data/maps.json` 的顶层加上：

```json
"feeds": [{ "label": "天城执法局开放数据", "url": "https://example.com/tiancheng/events.json", "every": 300 }]
```

- 查看器启动后会拉取一次，之后每 `every` 秒（至少 60 秒）拉取一次。
- 接口返回 `{ "events": [ … ] }`，每一项的字段和标签完全相同。
- 数据源的事件会和聊天标签合并显示，地点卡里「来源」写 `label`。
- 数据源的事件没有楼层号，所以不会随楼数淡出；网络攻击事件在状态改成已恢复之前一直花屏。
- 示例见 `docs/feed.example.json`。
- 接口需要允许跨域（CORS），或者和查看器同源。
- `url` 也可以写相对 `map/` 的路径（例如 `data/feed.json`）。
- 默认不配置任何数据源。
- `tools/check_maps.py` 会检查 `feeds` 的格式。

## 字段与参考项目

事件归一化后的结构：

```
{ key, tag, label, title, place, sev, status, t, mes, src, map, marker, nx, ny, approx, glitch }
```

它和下面这些犯罪 / 火情数据项目的最小输入对齐，以后做时间轴和热区时可以直接复用。

| 项目 | 许可 | 可借鉴 |
|---|---|---|
| [adaj/predspot](https://github.com/adaj/predspot) | BSD-3 | 输入只要 `tag, t, lon, lat`；网格 / KDE 热区、时间序列分解、按网格预测下一时段风险 |
| [apwheele/crimepy](https://github.com/apwheele/crimepy) | MIT | aoristic 时间分摊（事件只知道大概时段时如何分到小时）、DBSCAN 热点聚类、Folium 地图 |
| [Geobuddy/Crime-Dashboard](https://github.com/Geobuddy/Crime-Dashboard) | MIT | 热力图 / 聚合点 / 分区着色三种视图，按类型与日期筛选，地图旁的数据表 |

## 分阶段

1. **已完成**：
   - 标签协议；卡内扫描与角标；查看器打点、地点卡、开关、世界图角标；
   - 网络攻击花屏；
   - feeds 数据源；
   - 世界书条目与视觉规范样例。
2. **时间轴与筛选**：地图底部一条楼层 / 剧情时间滑条，按类型开关；地点卡旁列出同一地点的历史事件（参考 Crime-Dashboard）。
3. **热区**：按 `tag` 统计各地标或网格的累计事件，用半透明色块叠加，只在缩小时显示（参考 predspot 的网格计数，不做预测）。
4. **地图反哺剧情**：查看器把「当前地图附近未解除的事件」回传给卡内脚本，写进变量（MVU），让角色在对话里自然提到。例如走到 7 号井附近时，知道那里刚着过火。
5. **城市自己运转**：用 feeds 接一个自建接口，按时间自动生成停电、交通、天气之类的背景事件，让城市在对话之外也在变化。
