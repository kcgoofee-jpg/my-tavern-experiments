## 用户定下的要求（汇总）

1. 作者为自己的卡发布地图之后，其他用户可以做「自己的岛」，并和别人的岛联动显示。
2. **我们不提供建造网页**。建模、贴图、渲染由用户自己完成、自己上传、自己托管。
3. 我们只负责两件事：**兼容**（定格式、能加载、能显示）和 **ID 管理**（谁是谁、放在哪、不冲突）。
4. 核心目标：**地图里能显示别人的岛**。
5. 电脑端优先；默认用户全程联网、有梯子、网速快。
6. 公开内容只有仓库所有者能放行（与图集相同：本地私用随意，进公共列表要所有者合并）。
7. 不做内容审查逻辑；技术上只防「会执行代码 / 会拖垮页面」的东西。

## 设计

### 1. 岛资源包（用户自己做、自己托管）
- 一个文件夹：`island.json`（清单）+ `island.glb`（标准）+ 可选 `island_low.glb` + 可选俯视 / 斜视贴图 `top.webp`、`oblique.webp` + 可选 `cover.webp`。
- 托管在用户自己的 GitHub 公开仓库（经 jsDelivr 按提交号分发，内容不可变）。只接受 GitHub / jsDelivr 地址，其他域名一律不加载。
- `island.json` 字段：`schema`、`id`（见下）、`name`、`author`、`pack`（属于哪张卡的地图包）、`layer`（放在哪层，如 `tc_upper`）、`size_m`（真实半径）、`alt`（高度，走纵深系统）、`underside`（可选，岛底参数）、`files`（相对路径 + sha256 + 字节数）、`license`。

### 2. 兼容规则（地图这边做）
- 只加载 glb / webp / json，没有脚本、没有 HTML。
- 大小上限：标准 glb ≤ 8 MB、低配 ≤ 3 MB、贴图 ≤ 4 MB；超限拒绝加载并提示。
- 校验 `files` 的 sha256，对不上就不显示。
- 渲染：主地图（斜视 / 俯视）显示岛的贴图；点开进三维看 glb；纵深系统按 `alt` 给雾和缩放，和官方岛同一套规则。
- 失败降级：资源拉不到就只显示一个带作者名的标记点。
- 发一个校验脚本 `tools/check_island.py`，用户上传前自己跑，结果与地图加载时的检查一致。

### 3. ID 管理（我们维护）
- 注册表 `map/data/workshop/<pack>.json`：`id → {作者 GitHub 名, 资源仓库@提交号, 放置位置 slot, 状态}`。
- `id` 格式：`<GitHub 用户名>.<岛名>`，天然不撞名；同一作者多岛用不同岛名。
- 位置：每个地图包在纵深系统里预留若干「工坊槽位」（高度 / 远近 / 平面坐标），注册时分配槽位，避免岛叠在一起、挡住卡内岛。
- 登记流程：用户在仓库开 issue（模板）→ 自动校验（GitHub Action 跑 `check_island.py`）→ 所有者合并注册表 → 下一次推送后全部用户可见。
- 下架：所有者把状态改为 `hidden` 即可，不删历史。

### 4. 联动
- 地图设置里「工坊岛」开关（默认开）+ 只看某些作者 / 全部。
- 用户本地可以先「试装」自己的岛（填资源地址，本机可见，不进注册表），确认没问题再申请登记。
- 岛之间联动（互相拜访、航线）第一版只做「显示 + 点开看 + 作者信息」；互动放以后。

| 地图加载 / 校验 / 降级显示 / 三维查看 | 6–8 h |
| 本地试装 + 设置开关 | 2–3 h |
| issue 模板 + GitHub Action 自动校验 | 2–3 h |
| 文档 + 示例岛包 | 2 h |
