## 1. 总览

### 卡里写的
- 新历 2088 年【卡 L26】。天城以太魔法与科技并行，全城四季分明、没有极端天气，气候由以太气候调节塔人工维持【卡 L28】。
- 上层是「悬浮庄园区」，离地 800–1500 m【卡 L32】：
  - 数十座独立悬浮岛，靠以太引擎浮着；
  - 每岛一座私人庄园，占地数千到数万 m²，各带结界；
  - 总人口不到 2000 人，占全城七成以上资源，全面免税；
  - 空域由议会骑士团巡逻，**没有公共交通**。
- 交通：
  - 私人悬浮载具是上层唯一的交通方式，价格 500 万–3000 万 Æ，落点是各庄园的「访客停靠平台」；贵族载具可无阻通行所有层级【卡 L98】。
  - 骑士团另有悬浮机动装置，用于短距离飞行和高速移动【卡 L105】。
  - 交通靠以太驱动引擎，通讯靠通讯水晶和「霓讯」App【卡 L113】。
  - 卡里没有飞艇【卡 L12、L318】。
- 上层与中层之间要身份验证和通行许可，许可由执政厅签发，编号 P-xxxxx【卡 L109】；视觉样例里的跨层许可写明「中层 → 上层」和有效时段【卡 L302】。
- 银冠堡是议会骑士团总部，一座悬浮要塞，在上层与中层交界【卡 L48、L152】；骑士团 12 个分队，每队约百人，巡逻据点在中层高区【卡 L56、L367】。

### 仓库推断
- **魔导科技统一语汇**：
  - 结界：贴地扁穹，穹面是六角蜂格，平时几乎透明；访客通过时，平台开口处的格面会亮起。
  - 崖边斜伸出能量晶簇。晶簇多少按身份分级：罗斯柴尔德 > 银冠堡 > 首相府 / 精英学院 > 私宅。
  - 岛底是以太悬浮核心：倒悬岩锥、导能脉、符文环引擎、压舱晶。俯视看不到，只在三维和斜俯视图里出现。
  - 停靠平台：一圈引导信标，加一条进场光带，平台上停密封式悬浮车（无旋翼、无机翼）。
- **建筑**：英式乡村庄园 × 2088 材料，例如合金檐口、玻璃连廊与玻璃穹、全息园灯、离地悬浮的玻璃亭和光球花钵。
- **流线**（卡依据 L32、L98、L105、L109）：
  - **海拔航层**：上航层约 1300–1500 m，中航层约 1050–1300 m，下航层约 820–1000 m。同层之间直飞，不设固定航线，避免读成公交。
  - **进场走廊**：只由信标定义，不画实体。宽约 60 m，长约 400 m，下滑角约 5°。
  - **银冠堡升降井**：以银冠堡为轴、半径约 800 m 的柱状空域，是上中层之间唯一合法的垂直通道。
  - **许可核验**：许可由中层执政厅签发【卡 L109】，在升降井口的检查平台核验，由骑士团执行。
    - 贵族载具走信标握手的绿色通道【卡 L98】；
    - 持 P-xxxxx 许可的来客要短停核验。
  - **骑士团空域**：
    - 外环巡逻圈在 1000 m 上下；首相府周围 300 m 是禁停圈；
    - 分队从中层高区的据点上行【卡 L56、L367】；
    - 画面里最多出现几个小亮点编队，不画航迹线。
  - **以太导能管只输能**：不载人，不载货。数量少、光暗，只从以太气候调节塔放出，**从不连伊甸**，不连停靠平台。详见第 5 节和 Q1。
- **社会两条轴**（小说家）：
  - **高度 = 位阶**：越接近 1500 m 上限，越被默认为站稳脚跟的旧势力；越低，越被读作资历浅或近年财势松动。
  - **距离 = 隐秘度**：常被看见的家族和机构聚在核心圈；熟人可访的退后一层；刻意隐身的沉在远处和雾里。距离是每家选择被看见多少的结果。
  - 伊甸放在高而近的位置，暗示它是正在被上层接纳的「新客」：地位未定，但摆在人人看得清的地方。
- **停靠礼仪**：岛与岛之间没有任何固定连接，所以每一次拜访都是社交事件。谁的车停在谁的平台上，本身就是消息。平台因此是全岛除正门外装饰最考究的地方。
- **新技术、旧礼仪**：请柬、品鉴、拍卖、宴会刻意保留前魔导时代的形式。
  - 以太只进细节，例如请柬要接触结界密钥才显字，温室用微型以太场养南方花卉。
  - 这些只作氛围，不当地标事实。
  - 建制年代卡没写，只写「数代以来」，不编年份。

## 2. 上层纵深系统【仓库推断】

### 原则
- 画面里只有 9 个实体：7 座卡内岛 + 银冠堡 + 以太气候调节塔。**不画任何无名岛，也不画云里露出的岛尖。**
  - 卡说数十座【卡 L32】：其余都在画框外。岛与岛之间的留白和空云，就是 800–1500 m 空域的尺度感。
- 纵深全靠写实的大气和光学手段：缩放、雾、色偏、云层。不用描边、光晕，也不投影。
- v11 的 x / y 位置已获批准，**不动**；本节只调海拔和深度参数。
- 三维模型仍按真实尺寸贴，缩放只作用在俯视构图上：绕岛心缩放，不改地图坐标。

- **云片**：三张独立的高度层 alpha 云片，c1 约 1150 m、c2 约 1020 m、c3 约 930 m。越往下的岛被叠的云越多，这就是「往下看」的感觉。云片只从岛之间穿过，关闭阴影，岛不接收云影。
- **调节塔是纵深标尺**：唯一贯穿各档的竖向物。看塔身被哪层云切断，就知道那一档有多低。
- **结界规则**：
  - 俯视只画一圈淡六角格边，随距离衰减；
  - 扁穹只在三维和斜俯视里出现；
  - 例外一：「Y」的庄园在远景里仍保留一道冷光细边，是远景里唯一看得到的结界；
  - 例外二：伊甸**不画任何结界边**。
- **色温例外**：近暖 → 中性 → 远冷是基本规律。罗斯柴尔德的冷蓝晶光和「Y」的冷边是刻意打破规律的两处，用来把视线引向「最有钱」和「最神秘」的庄园。
- **标签规则**：
  - 只用卡原名；白字，深色半透明底，不按岛着色，避免读成势力图；
  - 锚点在岛北侧外沿，用引线指向主建筑，不压屋顶；
  - 开视差时，标签跟着所在岛的视差层一起移动；
  - 缩放到 2× 起，远岛标签逐步恢复，4× 时完全恢复。
- **读图顺序**：
  1. 伊甸：全图最亮最暖，首屏就停在这里；
  2. 凯莉的宅邸、首相府、罗斯柴尔德：各靠一个主建筑剪影认出；

  5. 调节塔竖贯全图；
  6. 最底是云海，只做遮挡，不做影。

## 3. 通用悬浮岛解剖【仓库推断】

以半径 R 的岛为例，从上到下：

1. **结界壳**：贴地扁穹，顶高约 0.35R。
2. **岛面**：庄园用地半径约 0.85R；外圈是崖缘林带和合金石栏；停靠平台（约 30×20 m）从岛缘悬挑出去，平台内缘就是结界门槛。
3. **岩盘**：厚约 0.25R，里面有地下室、储能库、集水槽。
4. **倒悬岩锥**：深 0.6–0.8R，锥面嵌有发光的石英状导能脉，锥尖垂一根压舱晶，用来稳定姿态。
5. **以太引擎**：位于锥体上三分之一，外露三道反向旋转的符文环。转速决定岛的高度，环光越亮，说明负载越大。
6. **维护檐廊**：环绕引擎的一圈窄悬廊，技师从岛面竖井下来检修。只在三维里出现。

岛底只被云遮住，**不投岛影**。

## 4. 各岛

### 4.1 伊甸庄园（焦点）
**卡里写的**
- 玩家的庄园，独占一座悬浮岛【卡 L46、L199】。
- 前庭有喷泉和访客停靠平台，平台也是结界边界；后庭有人工湖，上方是结界穹顶；外层结界覆盖全岛【卡 L226–229】。
- 结界发生器以太驱动、持续供能，卡没写位置；B2 是用户决定【卡 L242】。

**仓库推断**
- 空间 / 结构：
  - 沿用 estate2 白石新古典，不加魔导构件；
  - 岛底是全区最大的岩锥，深约 200 m，中段悬着一只清水倒锥（凝水蓄水体），从下方仰视像一颗倒挂的水滴，只进三维；
  - 停靠平台朝南悬挑。
- 地图读法 / 配色：
  - 全图最亮最暖：暖白石，翠绿草地配深蓝湖，湖是识别点；
  - **不画任何结界边**（「伊甸光环」已否决）；
  - 外层结界只写在停靠平台的展开态里：「访客停靠平台（结界边界）」；
  - 导能管不连伊甸。
- 历史与礼仪：伊甸是上层的「新客」。它被摆在最亮处，任何来访的车停在它的平台上，都会被其他家族看见并议论。

### 4.2 罗斯柴尔德庄园 · 悬浮岛 R-02
**卡里写的**
- 伊莎贝拉·罗斯柴尔德的居所，她是军工与以太能源财阀的 CEO【卡 L47、L179】。
- 冬季宴会和品鉴宴在这里举行，凭请柬和结界密钥入场；品鉴宴由庄园主轮流做东，名次影响声望，拍卖前有预展【卡 L376】。

**仓库推断**
- 空间 / 结构：
  - 沃德斯登式府邸，外加冬园玻璃宴会厅和冬园台地；
  - 水景园中轴的长水池，池底铺冷蓝晶板，夜里整池发光；
  - 岛底挂一座「以太储能钟」：巨型晶体被合金笼架托住，是家族私有的能源储备；
  - 宾客大平台设结界密钥闸口；家族私用平台在岛背面。
- 地图读法 / 配色：
  - 蜂蜜色石配尖塔，冷蓝晶光全图最多，是暖石配冷光；
  - 魔导强度全区最高：崖缘晶簇多，岩锥上导能脉密布；
  - 悬浮岛 R-02 只放在展开态的副标题里。
- 历史与礼仪：
  - 财富根基是军工和以太能源的双重垄断，所以魔导外显做到「炫技级」，和旧贵族「藏而不露」的审美形成对照；
  - 冬季宴会延续数代，和联盟的冬季私人拍卖【卡 L377】前后相接，形成上层的「冬季社交季」。
- 传闻（只是传闻）：旧贵族私下说他们的爵位「买得比继承得多」，但联盟的拍卖和品鉴离不开罗斯柴尔德的能源技术，所以没人当面说。

### 4.3 首相府

## 5. 创新与性能（工程师）【仓库推断】

### 5.1 数据模式
- 唯一数据源是岛数据 JSON。
- 手填字段：
  - `altitude_m`：真实海拔，z 由它派生；
  - `dist_tier`：near / mid / far / horizon；
  - `depth_bias`：±0.3，手动推远或拉近。
- 派生字段：`tools/depth_derive.py` 算出后回写 `derived`，不手填。
- 公式（线性，便于调参）：
  - d = clamp(0.55·(1 − alt_n) + 0.45·dist_n + depth_bias, 0, 1)
  - scale = 1 − 0.42·d
  - haze = 0.05 + 0.6·d²
  - ward_alpha = 0.55·(1 − d)^1.5
  - 标签字号 = 15 − 4·d px，不透明度 = 1 − 0.45·d；d > 0.8 时只显示图标
- 示例：海拔按第 2 节合并表；伊甸的 ward_alpha 固定为 0。

### 5.2 渲染管线（Blender 单场景）
1. **缩放**：`depth_apply.py` 逐岛绕岛心缩放，地图坐标不变；在 `render_all.sh upper` 前执行。
2. **雾和色偏**：在合成器里用 Z 通道加逐岛 Cryptomatte 蒙版施加 haze，混向 tint；对比度随距离降低。不用体积雾，体积雾慢且噪点多。
3. **云片**：c1 / c2 / c3 三张程序化噪声云，烘成 4K alpha 纹理，每层覆盖率 15–30%。关闭 shadow，岛不接收云影。
4. **结界**：六角格边的发射强度乘 ward_alpha；伊甸为 0；「Y」保留一道冷边。
5. **输出**：beauty、逐岛 mask、每层云 alpha 分别出 EXR。

### 5.3 网页 viewer
- **视差分层**：云 c1 / c2 / c3 和岛组 near / mid / far，平移时位移系数 1.0 / 0.97 / 0.94。缩放时系数收敛到 1，保证热点对齐。**采用。**
- **近岛叠加层**：只有近档和中档的 5 座岛做独立的 alpha PNG，远岛留在底图里。**部分采用。**
- **漂浮**：叠加层上下 ±2 px，周期 8–14 s，各岛相位不同；遵守 prefers-reduced-motion。**采用。**
- **云流动**：UV 平移，c1 最快，c3 最慢。**采用。**
- **热点**：点击区和叠加层用同一个 transform，避免视差导致点不准。
- **真三维**（three.js 摆 glb）：暂缓。

### 5.4 一致性
- `depth_derive.py` 同时输出三样东西：Blender 参数、`web/upper_depth.json`、瓦片清单。
- 8K 底图 = beauty 用 mask 挖掉近 / 中档岛后补云；叠加层是同一次渲染的逐岛 2K 裁切。像素严格对齐，也不用重渲。
- CI 自检 `tools/check_depth.py`：
  - 叠加层和底图的 IoU ≥ 0.98；
  - 每个热点落在对应岛的 mask 内；
  - 标签之间无重叠。

### 5.5 推广
- `depth_model` 做成层级配置：中层（楼高）、下层（地面）只换 alt_range。
- 包作者只填 `altitude_m` 和 `dist_tier`；没填时默认 d = 0.3。
- 视差和漂浮逻辑放进通用模块 `depthLayers.js`，由各层 manifest 开关。

### 5.9 游戏式悬停聚焦（桌面优先）
**效果**：鼠标移到岛上，岛轻微放大、上浮，它的标签和结界变亮；点击选中；再点「进入」，镜头飞进该岛的详情视图。

**命中检测**
- 用 5.2 输出的逐岛 mask 生成多边形：`tools/depth_derive.py` 对每张 mask 取轮廓，Douglas-Peucker 简化到 ≤ 64 点，写进 `web/upper_depth.json` 的 `islands[].hit_poly`。
- 运行时做点在多边形内测试（射线法），先用 bbox 粗筛。重叠时取 d 最小（最近）的岛。
- 多边形跟随岛所在视差组的 transform（与 5.3 热点同一 transform），所以视差平移时不会错位。
- 远档（d > 0.8）岛命中区外扩 6 px，否则太小难点。

**状态机**：`idle → hover → selected → entering → detail`
- idle → hover：指针进入多边形，延迟 60 ms 防抖。
- hover：叠加层 scale 1.00 → 1.04、上移 4 px；标签不透明度升到 1、字号 +1 px；结界发光 ×1.6（伊甸 ward_alpha 为 0，改为亮标签和轮廓光）；其余岛降到 0.85 亮度。
- hover → idle：离开 120 ms 后回落。
- 点击 → selected：保持 hover 外观，弹出信息条（名称 + 「进入」按钮）；点空白或 Esc 回 idle。
- 「进入」→ entering：镜头以岛心为目标缩放 + 平移，600 ms；视差系数随缩放收敛到 1（沿用 5.3）；结束后加载该岛详情视图（已有的独立地图 / glb），失败则停在 selected 并提示。
- 缓动：hover 进入 180 ms `cubic-bezier(.2,.8,.2,1)`，退出 220 ms ease-out；entering 600 ms ease-in-out。prefers-reduced-motion 时去掉缩放和上浮，只改亮度，entering 改为 150 ms 淡入淡出。

**只能放大有叠加层的岛**：5.3 只给近 / 中档 5 座岛做独立叠加层。远岛留在底图里，无法单独缩放，只做标签和轮廓光（轮廓由 hit_poly 画成 1–2 px 发光描边，叠加发光，不是矢量画）。如要远岛也放大，得给它们也出叠加层，P2 多约 2 h。

**键盘和无障碍**
- 每座岛对应一个不可见的 `button`（`aria-label` = 岛名），Tab 按 d 从近到远排序；焦点 = hover 外观，Enter = 选中，再 Enter = 进入，Esc 退回。
- 焦点环用标签外框显示，不只靠发光。

**触屏退路（无 hover）**
- 第一次点 = 选中（显示 hover 外观 + 信息条）；再点同一岛或点「进入」= 进入。
- 用 `pointerType` 判断，不用 UA；命中区外扩 10 px。
- iPhone 最低优先级，按报告修。

**和其他层的关系**
- 与漂浮叠加：hover 的 scale / 上浮叠在漂浮 transform 之上，不重置相位。
- 与云层：c1 云片在 hover 岛前方时，局部降低 c1 alpha 到 0.6，避免看不见放大效果。
- 与结界 shader（5.7）：只传一个 `focus` uniform，不另写 shader。

### 5.10 创意工坊可行性（用户自建岛并互联）
**设想**：作者为卡发布地图后，用户自己造一座岛，挂到这张图上，并和别人的岛连起来。前提：桌面优先、始终在线、网速快。以下只谈技术。

**造岛方式**
| 方式 | 内容 | 优点 | 缺点 |
|---|---|---|---|
| A. 模板 / 套件 | 选岛形（5–8 种底座）、生态（花园 / 雪 / 晶簇 / 废墟）、从魔导套件（5.7）摆建筑，网页内 three.js 拼装 | 风格统一，文件小（只存 JSON 参数），不用 Blender | 要先把套件导成 glb 零件库；可玩性受套件大小限制 |
| B. 上传完整模型 | 用户上传 glb | 自由度最高 | 风格不一致；只能校验体积和面数：glb ≤ 8 MB、≤ 150k 三角面、纹理 ≤ 2K、必须 KTX2 或 WebP |
| C. 上传渲染图 | 用户上传带 alpha 的岛图 + mask | 最省事，接入现有 2.5D 管线 | 光照和视角很难对上 |

建议先做 A，B 作为高级选项，校验只做大小 / 面数 / 格式。

**存储与分发**
| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| GitHub PR / issue + jsDelivr | 用户提交 issue（附 JSON / glb），GitHub Action 校验后合进仓库，走现有 jsDelivr（`build_preview_script.py` 已用 cdn.jsdmirror.com + cdn.jsdelivr.net） | 零服务器、零费用、与现有发布链一致 | 用户要有 GitHub 账号；合并有延迟（分钟到小时）；jsDelivr 缓存需清（已有 `warm_cdn.sh` 类工具）；仓库会膨胀，glb 需另开数据仓库 |
| Cloudflare Workers + R2 + D1 | Worker 做上传 API，R2 存 glb / JSON，D1 存索引和链接 | 即时发布；R2 无出口流量费；免费档够小规模 | 要维护服务端和密钥；需要身份方案；国内访问 Cloudflare 不稳 |
| 其他（Supabase / Firebase） | 托管数据库 + 存储 + 登录 | 登录现成 | 国内访问更差，锁定供应商 |

**身份**：GitHub 方案直接用 GitHub 用户名；Cloudflare 方案可用 GitHub OAuth 或「首次生成密钥对、存本地」的匿名作者身份（岛 JSON 带公钥签名，只有持钥人能改）。

**互联与发现**
- 每张地图发布一个 `workshop_manifest.json`：岛 id、作者、版本、文件 URL、落位槽。
- 落位槽：在纵深系统（第 2 节）里预留槽位，每个槽给定 `altitude_m` 和 `dist_tier`，用户岛自动套 5.1 的 scale / haze，保证不抢主岛；建议只开 far / horizon 档，每图 12–24 槽。
- 连接：岛与岛之间用「导管」（魔导套件里的导管件）连线，manifest 里存 `links: [[a,b]]`，双方都同意才显示。
- 发现：viewer 里一个列表面板（按最新 / 连接数排序）。

**外部脚本能否承载**：可以承载「看」——TavernHelper 外部脚本已经从 jsDelivr 拉取资源，再多拉一份 manifest 和若干 glb 没有问题。「造」和「上传」建议放在独立网页（同一仓库的 GitHub Pages），脚本只放一个链接；不要把编辑器塞进聊天界面的 iframe。

**成本**：GitHub 方案约 0 元。Cloudflare 方案在免费档内（R2 10 GB、Workers 每天 10 万请求）基本 0 元，超出后每月几美元。开发工时见下。

**技术风险**
- 性能：同屏几十座用户 glb 会拖垮 Mac TT；必须用 2.5D 缩略图（服务端或提交时渲一张），只有进入该岛才加载 glb。
- 兼容：用户 glb 的材质五花八门，需要在校验时统一到 PBR 基础材质。
- 版本：主地图改版后槽位坐标变化，manifest 要带 `map_version`，旧岛按槽位 id 而非坐标挂载。
- 依赖：jsDelivr 单包大小和缓存策略；Cloudflare 国内可达性。

**分期 MVP**
| 阶段 | 内容 | 小时 |
|---|---|---|
| W0 | 槽位写进纵深数据、manifest 格式、viewer 读取并显示外部岛（只读） | 8 |
| W1 | 模板造岛网页（岛形 + 生态 + 套件摆放，导出 JSON） | 25 |
| W2 | GitHub issue 提交 + Action 校验 + 合并入数据仓库 | 8 |
| W3 | 导管互联、发现面板 | 10 |
| W4（可选） | 迁到 Cloudflare 即时发布、glb 上传 | 15 |
| 合计 | | **约 51 h（不含 W4）** |

**建议**：可行，但**现在不做**。前置条件是 5.7 魔导套件、5.9 悬停聚焦和纵深槽位都已上线，且正式发布之后（目前发布暂停）。届时先做 W0 + W2（GitHub + jsDelivr，零服务器），用真实投稿量决定是否做 W1 编辑器和 W4 Cloudflare。

## 9. 斜视视角补充设定（v3 新增，待用户确认；全部【仓库推断】，只列卡依据）

用户决定：上层主地图改成 2.5D 斜视成图（参考张家界 / 阿凡达式悬浮山：岛底收成尖锥、瀑布坠入云海、上下层次一眼可读）。另有真三维模式，以后由别的任务用同一份纵深数据做。

### 9.1 全场
- **相机**：
  - 从南偏东 15° 看向北，俯角 35°，焦距 50 mm 等效；画幅 16 : 10（≈ φ）。
  - 伊甸放在水平正中、竖向离顶 0.618 处（黄金分割线）。它最近最高，所以落在画面前中部。
  - 其余岛按海拔向画面上方和后方退：越低越远，也越靠上、越小。同一套纵深数据（`upper_depth.json`）直接决定它们在画面里的上下。
  - 为什么选 35°：30° 以下岛面会被压扁，看不清庄园；45° 以上又看不到岛底和瀑布。35° 时岛面和岛底的面积大约是 φ : 1。
- **光**：
  - 下午，太阳在西南、高度约 40°。和中层、下层底图同一方位，岛底朝东北的一面落在阴影里。
  - 岛底的以太核心自发光，在阴影面里最显眼。
  - **不给云面投岛影**（用户未批准）。岛与云之间的层次靠雾和云片表达。
- **云海三层**：
  - c1 约 1150 m：碎云絮，从岛之间穿过；
  - c2 约 1020 m：薄纱带；
  - c3 约 930 m：厚云海顶，银冠堡和「Y」的岛底没进去。
  - 在斜视里，每层云是一条横向的亮带，越往画面上方（越远）越连成片。
- **中层透出**：画面右上远处，c3 云隙里露出一线极淡的中层楼顶天际线（约 8 % 不透明）【卡 L32：上层俯瞰中层】。
- **天空**：画框上缘留约 12 % 的淡蓝灰天空，远处云海顶融进去，不画地平线上的城市。

### 9.2 通用岛底解剖
- **岩体**：崖缘下先是约 30–60 m 的竖直崖壁，看得出层理；然后收成一个或几个倒锥，锥尖约为岛径的 0.8–1.2 倍深。张家界式石柱只用在个别岛。
- **悬浮核心**【卡 L32：以太引擎维持悬浮】：
  - 嵌在倒锥中段，是一颗发光核，外面两圈符文环缓慢错转；
  - 导能脉沿岩缝向上爬到崖缘，和岛缘符文环接上。
- **晶簇**：崖壁和锥体上斜伸出冷蓝能量晶簇，越靠近核心越密。
- **垂根**：林地岛的崖缘垂下气根和藤蔓，约 10–20 m。
- **结界**（斜视）：
  - 一道很淡的扁穹，只在穹顶的弧边上看到一圈六角格反光，穹面本身基本透明；
  - 远岛只剩弧边细线，或者看不见；
  - 伊甸不画；「Y」只有一道冷光弧边。
- **停靠平台**（斜视）：
  - 从崖缘悬挑出去，底下有斜撑回到岩体；
  - 平台外沿一圈引导信标，一条进场光带沿下滑角约 5° 向外伸出约 60 m（只是光点，不画实体航线）【卡 L98：落点是访客停靠平台】；
  - 平台上停一两辆密封式悬浮车（无旋翼、无机翼）【卡 L12】。

### 9.3 水与瀑布（水往哪里去）
- **原则**：瀑布坠出崖缘后在约 200 m 内碎成水雾，混进下方云片。
- **补水**：
  - 岛底倒锥里有「凝水 / 回收」环，把雾里的水汽重新凝回岛上。这符合「以太维持气候」的设定【卡 L28】。
  - 斜视里看不到这个环，只在三维模式里做一圈淡蓝凝结环。
- **伊甸庄园**【卡 L227：后庭人工湖】：
  - 人工湖的溢流沿东侧沟谷（有吊桥的那条）流到东崖，化作一道主瀑布加两道细瀑；
  - 瀑布正好落在画面的伊甸右侧，把伊甸和下面的云海在竖向上连起来。

### 9.5 标记与遮挡（斜视地图）
- **锚点**：每座岛存一个三维锚点 (x, y, alt)，放在主楼顶上方 20 m。用成图相机矩阵投影到瓦片坐标。
- **相机矩阵**：写进成图的 `meta.json`，前端标记和将来的真三维模式都读这一份。
- **遮挡**：
  - 某岛被前面的岛体挡住超过 40 % 时，标签上移到它可见部分的上沿，用一条引线指过去；
  - 完全被挡住时，只在它露出的那块云里放一个小点，点按才展开。
- 这些规则写在 `docs/design/depth-system.md` 的「view: oblique」。
