# Naming — rules, rename map and glossary

> Canonical English edition; Chinese edition: `docs/naming.zh.md` (same heading structure, gated by
> `tools/check_zh_mirror.py`). Product of plan step S0.4 (decision D12). **This file changes no code: nothing has been
> renamed.** Internal names are renamed in S5 (with the file split), external contracts in S10 (with a migration and a
> re-confirmation by the user, decisions D5 and D12). Every row was checked against the code at head #101
> (2026-09-30); the module map it builds on is `docs/ARCHITECTURE.md` §3. UI wording has its own glossary,
> `docs/i18n-glossary.md`; this file is about code and data names only.

## Naming rules

1. **File names state the job.** English words, kebab-case, `.mjs` for modules (`.js` only for classic scripts that attach to `window`). No pinyin, no unexplained abbreviation, no card or pack name. A reader who sees only the file name can say what it does.
2. **One concept, one name, repo-wide.** The glossary below is the authority. When a concept has several names today (stash / pickup / loot / inventory), the tables pick one. Add a term to the glossary before using it in code.
3. **Shared symbols have at least 3 letters and carry meaning.** This covers exports, `window` names, protocol constants and module handles used across files; loop counters and one-line locals are exempt. Established acronyms stay as written: `MVU`, `DZI`, `LOD`, `i18n`, `URL`, `DOM`, `SVG`, `CDN`, `FPS`, `RNG`, `UI`. Everything else is spelled out (`th`, `wb`, `cvd`, `ctx`, `ops`, `inv`, `nm`, `tx` are not on the list).
4. **Same-name files are told apart by a role suffix.** When one name exists in two folders, the pure core side keeps the bare name (its folder already says "core"), the viewer side adds `-view`, and the host side that derives data from chat text adds `-parse` (otherwise a job word such as `-templates` or `-gateway`). If the two files are about different things (`budget`, `layers`), each gets its own concept name instead.
5. **No card or pack names in engine identifiers.** `TC` (the sky city), `eden` and `estate` used as engine words go; the neutral product name is "Spatial Map / Spatial OS" (D5), so identifiers say `spatial` / `Spatial`. Pack data (`map/packs/**`, `map/data/**`) and builder tools (`tools/**`) are exempt.
6. **`window` globals exist only where a non-module consumer needs them** (classic scripts, browser probes, the host). Shape: `<Concept>Api` for a singleton, `<Concept>View` for a viewer plugin, `__camelCase` for debug and handshake hooks. Every global has a row in table C; a new one is not accepted without a row.
7. **Persisted and cross-version names are contracts.** Chat-variable keys, storage keys, protocol types, worldbook `extra` fields, tag grammars, the entry file, CDN paths and package names change only in S10, with a one-time migration: read the new name, fall back to the old one, write the new one, keep the old one readable for at least one release, never delete user data. Anything that lives inside stored chats (tag grammar, `data-tcmap`) is accepted forever. Names owned by someone else (the character card) are never renamed.
8. **Chat-variable keys are ASCII camelCase.** Values that are data (a place name, a user's custom text) stay data.
9. **Renames are scripted and import-aware.** The short names (`P`, `M`, `T`, `cur`, `est`, `LS`, `NT`, `nm`, `lp`) also exist as unrelated locals in other files, so a text search-and-replace is wrong: use a parser-based rename or review every hit. One rename batch is one commit series with the full test suite green at the end.
10. **No collisions.** Every proposed file path is new and unique. Every proposed identifier occurs nowhere in `map/` or `tests/` as a token, with three exceptions that were looked at: `storage`, `plugins` and `protocol` appear only as property names or inside path strings, never as declared identifiers, and `uiTextOr` is shared on purpose by `tx` and `T` (they merge). Re-run this check before S5 starts; head moves.

## Rename map

One table per class of name. Nothing here is decided until the user reviews it; the "Proposed name" column is the draft for that review. Entries whose proposed name is `(keep)` are listed only so the table is complete.

### Reading the tables

- **Current / Where** — the name as it is in the code, and the file and line of its definition (`:1` = the whole file).
- **Meaning** — one line, checked against the code (header comment and body), not guessed.
- **Proposed name** — the draft new name. `(keep)` = no change; `(delete)` = the file goes away.
- **Class** — *internal*: seen only by our own code. *external contract*: persisted or seen outside the viewer page (chat variables, storage keys, protocol types, `window.EdenMap`, the entry file, worldbook `extra` fields, npm name, CDN paths).
- **Wave** — `S5` internal batch, `S6` migrated by the stash unification (D4), `S10` external batch, `—` no change, `S5-1` a file S5-1 created under its final name (counted under no change).
- **Notes** — "refs" counts the files that name the item (imports, script tags, registry strings, `window` reads) in `map/`, `tests/` and `tools/`, found by script at head #101. It tells how far a scripted rename reaches; it is not a call-site count and can be off by a few. Comments and owner strings are included.
- **S5-2 status** — rows whose Notes end in "S5-2" (renamed, deleted or split) are done; the Current / Where columns keep the names of head #101 on purpose. `util.mjs` and `shell.mjs` were split by job in the same step (Decision (c)): `coordinates`, `dom-helpers`, `viewport-mode`, `protocol-stamp`, `screen-reader-announce`, `json-cache`, `text-lookup`; `control-column`, `drawer-glue`, `notice-layer`, `status-dot`, `one-hand-mode`, `quick-zoom`.
- **S5-3 status** — rows whose Notes end in "S5-3" (renamed, retired or removed) are done, by `tools/rename_s5.mjs --globals tools/rename_s5_globals.json` (generated from tables C and D by `tools/rename_s5_globals_extract.py`). The Current / Where columns keep the names of head #101 on purpose. Where a row says one name and the code needed several (`cur` and its siblings and setters, the 11 `T` wrappers, the 21 module handles), the Notes list what was renamed; `storage.get` keeps its name.
