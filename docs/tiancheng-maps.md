# 天城三层地图：参考、真实感原则、脚本结构与接口

## 1. 可参考的同类背景

天城的骨架是「浮空岛 + 多层城市 + 阶级按高度分层」，外加「下层无光、层间设检查点、资源和人往上走」。下面几部作品的空间组织最接近，可以借来检验我们的地图是否可信。

| 作品 | 结构 | 对天城有用的地方 |
|---|---|---|
| 《最终幻想 VII》米德加（Midgar） | 离地约 50 m 的圆形上层钢板，由中央主柱加各区支柱撑起。板下是终年无光的贫民窟，按区编号（第 7 区），靠列车和板间通道连接。 | 与中层 / 下层几乎同构：支柱按网格分布；板下只有人造光；**层间通道是少数几个固定点，并且会聚成黑市和帮派据点**（7 号井 ≈ 七番街）。 |
| 《铳梦》撒冷 / 钢铁城（Zalem / Iron City） | 空中城悬在地面城上方，垃圾从底部倾倒成废料山，地面工厂通过输送管把物资往上送。 | **资源向上、废物向下**：下层的工厂、货运、管道都该朝竖井和支柱汇聚；上层正下方堆积落下的东西。 |
| 《生化奇兵：无限》哥伦比亚（Columbia） | 浮空岛之间靠天轨（skyline）和飞艇连接。富人区是园林与纪念碑，工人区是码头和棚屋。 | 上层各庄园要有**连接关系**：停靠平台、航线、巡逻线。岛的「体面程度」用园林尺度和建筑材质表达，不用更多装饰。 |
| 《杀出重围：人类革命》恒沙（Hengsha） | 双层城市：上层平台「盘古」遮住下城日照，下城全靠霓虹和全息广告照明。 | 中层就是这种感觉：**遮挡决定光**。浮岛正下方最暗，霓虹在阴影里更显眼。 |
| 《天空之城》拉普达（Laputa） | 单座浮岛，倒锥形岩基，岛上是园林。 | 上层岛屿的岩基形状、树根垂挂、岛缘石墙。 |

## 2. 真实感从哪来（按作用大小排序）

1. **尺度统一，处处可以量。** 1 单位 = 100 m，片区 3 km × 1.875 km，街区格 24 m，支柱间距约 300 m，楼高按真实层高折算。地图可信，主要靠任意两处之间的距离说得通，细节多少是次要的。
2. **光服从遮挡关系。**
   - 上层：白天直射光。
   - 中层：大部分光被浮岛挡住，影子按三层共用的太阳方向偏移（`tc.SUN_ROT`、`tc.shadow_offset`），与上层底图里的岛影位置一致；岛的正上方位置由查看器的「上层投影」叠加层给出。
   - 下层：几乎没有天光，光源只有钠灯、厂房、黑市。唯一漏下来的天光落在 7 号井的竖井口（已实现：冷色面光）。
   - 色彩映射一律用 Standard，宁暗勿曝。夜景的「真」来自光晕（Fog Glow）和溢光，不来自提亮。
3. **基础设施有流向。** 货运铁路、管廊、货梯都指向竖井和支柱（物资向上），排水、垃圾、废热往下。每条线都要能回答「从哪来、到哪去」。
4. **地价梯度决定密度。**
   - 离核心区和交通节点越近，楼越高、霓虹越密。
   - 下层的贫民窟挤在支柱之间的背阴处，厂房沿铁路分布。
   - 检查点和黑市周围最拥挤。
5. **交通分层。** 上层是空中航线加停靠平台；中层是悬浮轨道加主干道和连廊；下层是老旧地面铁路加步行窄巷。每层用自己的交通「语言」，一眼就能看出是哪一层。
6. **三层严格对位。** 同一随机种子生成同一张街道网。检查点和 7 号井、浮岛和它的投影在平面上重合，由 `tools/check_maps.py` 自动检查。
7. **美术只来自渲染，交互只来自代码。** 标记、结界、投影轮廓、航线都是查看器里可开关的叠加层，不烘进底图。

## 3. 脚本结构

```
blender/
  tc_common.py        共用：参数解析、材质、批量网格（box_mesh / Batch）、城市生成、相机与导出、Layer 运行器
  tiancheng_upper.py  上层：白天，浮岛与庄园，中层楼顶压在霾下作远景
  tiancheng_mid.py    中层：夜景霓虹，悬浮轨道，浮岛投影，地标
  tiancheng_low.py    下层：钠灯工业区，贫民窟，铁路，支柱柱基，地标
tools/
  render_all.sh       渲染 → 切瓦片 → 检查（本机或云端）
  make_dzi.py         大图切 DZI 瓦片
  check_maps.py       注册表、点位、瓦片、跨层对位的一致性检查
map/
  data/maps.json      地图注册表（名称、出处、别名、叠加层、跨层通道）
  data/tc_*.json      渲染脚本导出的点位（不要手改）
  art/tc_*.dzi        底图瓦片
  viewer.html         查看器
  tavern/eden-map.js  酒馆里的悬浮按钮 + 面板
```

### 层脚本的统一骨架（`tc_common.Layer`）

```python
layer = tc.Layer('tc_mid', seed=7001, bounces=4)  # 解析参数、清空场景、生成城市（第一个随机调用）
city, R = layer.city, layer.rng                   # 城市布局（三层共用）与本层自己的随机
...                                               # 建本层内容：tc.box_mesh 批量盒子、tc.Batch 小图元
layer.marker('checkpoint_c', (x, y, 0), r=.6)     # 登记地标：平面坐标 + 占地半径
layer.finish(world=(颜色, 强度), glare_opts={...})  # 相机 → 导出 map/data/tc_mid.json → 渲染
```

规则：
- **城市生成必须是第一个随机调用**，由 `Layer` 保证。各层只能在生成之后按 `kind` 重新配色、压低或删除（`tc.keep_mask`），不能再消耗城市的随机序列。
- 上层不另起种子（`seed=None`），岛屿沿用旧的随机序列，所以布局与 v0.7.0 逐字节一致。中层、下层各自另起种子。

### 命令行（三层一致）

| 参数 | 作用 |
|---|---|
| `--res N` `--samples N` `--out 路径` | 分辨率（宽）、采样数、输出路径 |
| `--crop x0,y0,x1,y1` | 只渲染一块（归一化，左上原点），用于在最终分辨率下检查局部 |
| `--preview` | 800px / 8 采样、不加光晕；显式给的 `--res` / `--samples` 优先 |
| `--data-only` | 只导出点位 JSON，不渲染（几秒） |
| 层参数 | 中层 `--glow` `--ambient`；下层 `--glow` `--lamp` `--ambient`；上层 `--haze` |

运行方式：`blender -b -P blender/tiancheng_mid.py -- ...`，或 `python3 blender/tiancheng_mid.py -- ...`（pip 装的 `bpy`，自带 OpenImageDenoise）。批量用 `bash tools/render_all.sh [upper mid low] [--res] [--samples] [--data-only] [--bpy] [-- 层参数]`。

### 导出格式 `map/data/tc_<层>.json`

```json
{ "extent_m": [3000, 1875], "layer": "tc_mid",
  "markers": [{ "id": "checkpoint_c", "nx": 0.6533, "ny": 0.868, "r": 0.02 }],
  "islands": [{ "id": "eden", "nx": 0.55, "ny": 0.4573, "rx": 0.0552, "ry": 0.0662, "rot": 0, "alt_m": 1150 }] }
```

`nx` / `ny` 是底图的归一化坐标（左上原点）；`r`、`rx` 按图宽归一化，`ry` 按图高归一化。`islands` 只有上层有。

### 注册表 `map/data/maps.json`（每张地图）

`title`、`parent`、`group`、`layer{name, sub, alt}`、`kind`（world / points）、`base`（DZI）、`data`、`focus`、`status: planned`、`overlay{type: dzi | barriers, label, src?, from?}`、`markers{id: {name, sub, cls, tag: set | inf, src, alias[], link?}}`。

- `overlay.from`：叠加层取另一张地图的数据。中层的「上层投影」就是取上层的 `islands`。
- `link: {map, marker, label}`：跨层通道。地点卡里给一个直达链接，打开目标地图后聚焦并展开对应地点。`check_maps.py` 会检查两端在平面上是否重合。

### 查看器消息接口

| 方向 | 消息 | 作用 |
|---|---|---|
| 酒馆 → 地图 | `eden-map:here {value}` | 当前地点（MVU「世界.当前地点」） |
| 酒馆 → 地图 | `eden-map:open {map}` | 直接打开某张地图 |
| 酒馆 → 地图 | `eden-map:sleep` / `eden-map:wake` | 面板关闭时休眠（关掉底图、释放瓦片内存）/ 重开时唤醒 |
| 地图 → 酒馆 | `eden-map:ready` | 地图程序就绪 |
| 地图 → 酒馆 | `eden-map:state {map, title}` | 当前地图，用于面板标题 |

### 加一个地标的流程

1. 在层脚本里建模型，调用 `layer.marker(id, 位置, 半径)`。
2. 在 `maps.json` 该图的 `markers` 里写 `name`、`tag`、`src`（设定原文，推断的部分写明「推断」）、`alias`；有跨层通道就加 `link`。
3. `bash tools/render_all.sh <层> --data-only`（只更新点位），或正式渲染。
4. `python3 tools/check_maps.py` 通过后再提交。

## 4. 性能

**渲染**
- 城市约 5.7 万个盒子用 numpy 一次建成一张网格，生成加建网格约 2 秒。
- 小图元（树、储罐、灯头）写进同一张 bmesh，避免上千个 bpy 物体。
- 夜景层 `bounces=4`：光主要来自近处的灯，少几次反弹看不出差别，渲染明显更快。
- 开了自动分块（2048），8000px 时内存不随分辨率平方增长。
- 点光按颜色共用灯光数据块。
- 云端 CPU 实测（2000px，16 采样，4 核）：
  - 中层 285 秒 → 228 秒（反弹次数从 12 次降到 4 次）。
  - 下层约 690 秒，改反弹次数后基本没变：下层的成本主要在约 4000 盏点光的采样上。下一步是把一部分路灯换成只有发光灯头、不投光的版本，或者按距离合并成少量较强的光源。
  - 上层约 60 秒。
- 调参先用 `--preview` 或 `--crop`，只改地标位置用 `--data-only`。

**查看器与悬浮窗**
- 底图是 DZI 瓦片，只加载看得见的部分。
- 清晰度档位限制最高层级。
- 数据文件缓存，启动请求并行。
- 面板关闭后先休眠 3 分钟再销毁。
- MVU 更新合并去重。
- 拖动按帧节流。
- 面板加了 CSS containment。
