## 0. 现行设定（D41，2026-10-02）

用户 2026-10-02：效果优先，地图这一侧的设定每个字都可以改；卡的事实不改。下面七条是协调者效果审计后定下的规则，渲染线按它们自检（没有用户审图，§0.8）。

### 0.1 主视图：斜视 2.5D，俯视是开关

- 上层、中层、下层的主视图都改成斜视成图，三层共用一套相机（§0.2）。上线顺序：上层 → 中层 → 下层（§0.9）。
- 为什么：现在的底图是正上方俯视，树和房子只剩屋顶，看起来是平的（用户 2026-10-02）。斜视里立面、树冠侧面、岛底、瀑布、悬浮轨道的高差都看得见。用户 2026-09-28 已经批准过上层斜视（`upper-setting.md` §9、§11），一直没有上线。
- **俯视保留为开关**（图层菜单里一个「俯视」开关，全局记忆，默认关）。俯视用现有的俯视底图（各层各时段的 `tc_*` DZI），不再为俯视出新图。某层的斜视底图还没登记时，这一层自动用俯视，开关不显示。
- 世界图和九张开局地点地图是地形图，仍用俯视（§0.5、§0.7）。
- 斜视里的图仍然是地图：正交投影，比例尺处处相同，任意两点的距离可以量（§2 原则 1）。

### 0.2 共用相机（上层、中层、下层同一套）

| 项 | 值 | 说明 |
|---|---|---|
| 投影 | **正交** | 不用透视；理由见下 |
| 方位 | 165° | 相机站在南偏东 15°，朝北偏西看。沿用 `upper_depth.json` `view.camera.az_deg`。街网斜着入画，立面不会正对镜头变成一排平板 |
| 俯角 | 35° | 视线与水平面夹 35°。南北距离在画面里压成 sin 35° ≈ 0.57；高 h 的点在画面里上移 h · cos 35° ≈ 0.82 h |
| 比例 | 0.44 m / px | 三层所有斜视底图（各时段、插图除外）同一米 / 像素；8000 px 宽 ≈ 3520 m |
| 画框 | 每层按内容拟合，16 : 10 | 该层内容（中心柱在本层高度范围内的投影，加上本层所有实体：岛、岛底锥尖、塔冠、楼顶）的投影包围盒外扩 3 %，短边补齐到 16 : 10。中层、下层约 3520 × 2200 m（8000 × 5000 px）；上层若有岛伸出中心柱，画框随之变宽，像素宽度按 0.44 m / px 增加 |
| 场景海拔 | 真实海拔 | 下层地面 z = 0；中层底板 z = 50 m（L33 下限），楼顶按真实高度；上层岛按 `upper_depth.json` 的 `alt`（800–1500 m）。三层放在同一套米制世界坐标里 |
| 太阳 | `tc.SUN_ROT` | 三层共用的方向（西南，下午）。相机在东南、太阳在西南：侧光，影子落向东北，读得出体量 |

**为什么用正交，不用 `upper-setting.md` §9.1 的 50 mm 透视**：

1. **合成对得齐**。上层岛在 800–1500 m，中层城市在 50–800 m。正交下同朝向、同米 / 像素的两张图只差一个平移，D40 合成（上层岛叠在中层图上）是像素级对齐；透视下两层的缩放随距离变化，只能逐张重投影。
2. **比例尺处处一致**。地图上能量距离、比例尺有效，3 km 宽的画面边缘不会出现广角拉伸和楼体外倒。
3. **标记投影是仿射变换**。地图米 → 像素是一个 2 × 4 矩阵，点、线、多边形投影后仍是直线和多边形；屏幕点 → 地面点有闭式解（附录 OBLIQUE-CODE）。
4. **外圈图同一投影**。外圈（§0.5）只是同一朝向、更大画框、更低分辨率的一张图，放位置靠同一套公式。
5. **瓦片任意缩放都对**。DZI 金字塔每一级都是同一投影，不用按缩放档重算。

纵深感不再靠透视缩小，而靠真实海拔的位移、雾、色偏和光（`upper-setting.md` §2 的雾、色偏、云通道保留，缩放通道在斜视里关闭）。

**岛底和瀑布在斜视里怎么露出来**：相机在南偏东、俯角 35°，岛的南侧崖壁和岛底的南半边朝向镜头。倒锥的锥尖在画面里落在岛的正下方偏下（深 D 的锥在画面里长 0.82 D），以太核心和符文环在岛底的阴影面里最显眼。瀑布竖直下落，在画面里是一道向下的竖条，长度乘 0.82；约 200 m 内碎成水雾，水雾在上层成图里是半透明 alpha，合成时透出下面的霾和城市。北侧崖壁看不到；需要它时去三维模式。

### 0.3 每张层图里有什么

- **上层**：只有岛，透明底（胶片透明，带 alpha）。内容：岛面与庄园、崖壁、岛底倒锥、以太核心与符文环、晶簇、垂根、瀑布与水雾、停靠平台与信标、结界弧（伊甸没有结界边，`upper-setting.md` §2）、以太气候调节塔、三张云片 c1–c3（半透明，按云密度给 alpha，夹在岛之间，所以低处的岛被云遮得更多）。**没有**不透明的云海底，**没有**城市。
- **上层视图的合成**（D40，查看器做）：最下是中层同时段的斜视图 → 按时段着色的高空霾（FOG-1 的雾色 token）→ 上层岛图。开关「显示下方城市」：开 = 霾薄，城市从云隙透出；关 = 霾加厚到几乎不透明，读成云海，云片照旧。卡里两种景观都成立（L363：上层能俯瞰中层灯火，也能清晨看云海）。上层不另做外圈图：画框外是中层外圈 + 霾（§0.5）。
- **中层**：完整画面，不透明。城市从 50 m 底板到楼顶，悬浮轨道、连廊、全息广告都在。上层的岛不画进中层图；岛正下方的天光被挡（白天是边缘很虚的暗区，§0.4）。银冠堡在上层与中层交界（L48），只画在上层图里，中层图里不重复。
- **下层**：完整画面，不透明。地面城市、支柱柱基、7 号井竖井口。中层底板不画（视线穿过它），但光照按「头顶有板」算（§0.4）。地下设施（最深约 200 m，L34）不剖开，只用标记表示。
- 三层的成图里都**没有文字、徽记、标签、航线**；这些都是查看器叠加层（§2 原则 7）。

### 0.4 分层光照（取代 §2 原则 2 的旧文）

总规则：色彩映射一律 Standard，宁暗勿曝；夜景的「真」来自真实光源、光晕（Fog Glow）和溢光，不来自提亮。**没有光源的地方不发亮**：夜里不许出现找不到灯的亮斑、亮雾、亮云。

**上层（悬浮庄园区）：四个时段，晨 / 昼 / 昏 / 夜各一张。**

| 时段 | 天光与太阳 | 岛上的光 |
|---|---|---|
| 晨 | 太阳低、偏暖，云顶镀金，云谷灰蓝 | 少数窗灯未熄；以太核心常亮 |
| 昼 | 直射太阳 + 天光，现状的白天 | 以太核心、晶簇只在阴影面可见 |
| 昏 | 太阳低、橙红，长影，云海一半入影 | 窗灯陆续亮起，停靠信标亮 |
| 夜 | 只有很弱的冷月光；天空和云接近黑蓝 | **真实灯光**：主楼窗（暖 2700 K，约六到八成亮，逐层逐间有差别，不是一片均匀）、园灯和路灯、喷泉与水池灯、停靠平台信标环和进场光带、结界弧的淡青反光（伊甸没有）、岛底以太核心和符文环（夜里最亮的冷光）、晶簇微光、调节塔塔冠与场环 |

依据：伊甸东侧长廊「早上看云海，夜里看中层灯火」（L214）；上层庄园各带结界、以太引擎维持悬浮（L32）。云在夜里只被月光和岛上的灯从上方照到一点暖边。

**中层（钢铁霓虹区，L33）：三张——昼、昏、夜；晨用昏的那张。**

- 峡谷光：中层的天光比上层暗。太阳只照到楼冠和高处立面，街面常年在阴影里；浮岛正下方天光被挡，是边缘很虚的暗区（不描边，不是硬影）。卡写「日照被浮岛和高楼挡住，大部分区域靠人造光」，又写部分地段有日照（L364）。
- **霓虹和全息广告白天也开**：昼约为夜间亮度的四成，在阴影街面里照样醒目；昏约七成，窗灯开始亮。
- **夜：整张网格都亮**，不是只有商业区亮。各区有自己的光：核心区楼冠一圈暖金、写字楼白窗；高区干净的白光和冷白，辉光大教堂立面泛光；商业区（C 区）霓虹和全息广告最密，品红、青色；外围居住区暖色窗灯为主、霓虹稀疏，环城军营带是探照灯和白色泛光；悬浮轨道是发光的线，列车带灯；主干道是车灯流。只有公园、运河、空地保持暗。
- 晨与昏共用一张：峡谷里低角度的太阳几乎照不到街面，晨昏的差别主要在天色，查看器在这张图上按时段加一层很轻的色调。

**下层（地基区，L34）：只有人造光，一个光照体系，两个班次。**

- 几乎没有自然光（L34）；从下层抬头是「灰暗的天花板、检修管道滴水」（L363）。不画太阳、不画天光、不出蓝天环境光；环境光只有钠灯反弹出的很暗的暖色。
- **白班**（06:00–18:00，对应时段晨、昼）：工厂全开，炉口和屋顶天窗透出橙光，蒸汽羽流被下方照亮；钠灯全亮；货运铁路有车头灯；7 号井竖井口落下全层唯一的天光——一道冷白光柱，在地面落成一块光斑。
- **夜班**（18:00–06:00，对应时段昏、夜）：工厂只开一部分，暗下去的厂房更多；钠灯照旧；黑市、酒馆、地下格斗场一带的零碎霓虹更亮；贫民窟里出现更多纯黑的角落；7 号井的竖井口没有天光，只有中层霓虹漏下来的一点紫青色。
- 「晨 / 昼 / 昏 / 夜」四张下层图作废（下层不存在白天的日照），见 §0.9 退役项。

### 0.5 尺度：中心柱、外圈、世界图

- **中心柱**：三层都画同一块 3000 × 1875 m 的片区（§2 原则 1、6，跨层对位不变）。天城人口约 3200 万（L28），这块中心柱只是城市的芯，城市向四周还有很远。
- **外圈**：城市不在画框边上硬切，而是往外淡出到一圈约 12 km 的低清外圈，再融进 FOG-1 的雾。
  - 外圈覆盖中心柱四周约 12 × 7.5 km 的地面；同一相机朝向，画框约 14 080 × 8 800 m，4000 × 2500 px（约 3.5 m / px），中心与本层主图画框中心相同。
  - 主图外缘的羽化带（FOG-1）压在外圈上；外圈越往外楼越稀、越暗、雾越厚，到外缘完全融进雾。
  - 外圈**不放标记，不新造地点**；已有标记的地点不在外圈重画。
  - 中层外圈：城市肌理继续向外，楼高随距离降低；外围居住区之后，环城军营带（L36）沿外圈继续成弧（同一地点的延续，不加新标记）。时段同中层：昼、昏、夜。
  - 下层外圈：工业带、编组场和货运铁路向外放射，贫民窟连片，钠灯点越往外越稀，最后全黑。班次同下层：白班、夜班。
  - 上层：不渲外圈；合成里画框外是中层外圈 + 高空霾 + FOG-1 的漂云。不画无名岛（卡写数十座岛，L32，其余都在视野外）。
- **世界图**：天城变成一块看得见的城市。昼图上是一块灰色的城市肌理；新增夜图，天城是全图最亮的一片城市光，圣都、原域等世界图上有标记的城市也各有一片较小的光；边界线按底图全分辨率重画成细线（现在是 4000 px 的边界图放大，发虚）。FOG-1 的城市外雾环在夜里取世界夜图。

### 0.6 相机矩阵是数据

- 每张斜视底图（每个时段、每张插图、每张外圈图）都带一个**相机文件**，和 DZI 一起发布，在 `maps.json` 里由该底图的条目引用。渲染脚本写出它（现有 `<out>.meta.json` 的 camera 段扩展而来），`tools/oblique_post.py` 把它复制到 `map/data/cam/`。
- 标记、标签、路线、事件标记、区划、结界、雾区的像素位置**全部**由相机文件从地图米投影得到；斜视像素空间里不手摆任何东西。
- `check_maps` 检查：同一层各时段的相机文件完全相同（同画框、同像素尺寸）；三层的朝向和米 / 像素相同（合成前提）；每个斜视标记都有地图米坐标；插图和外圈的朝向与主图相同。
- 规格（字段、公式、合成、点击反算、俯视开关）见附录 OBLIQUE-CODE。

### 0.7 其余效果审计条目（B3–B7，按建议执行）

- **B3 地标三维模型预算**：每个地标 glb 桌面档 4–8 MB（主力地标取上限），贴图 1–2K（基色、法线、ORM），网格 meshopt 压缩，贴图 KTX2（法线 UASTC，基色 ETC1S）；手机档 ≤ 2 MB、贴图 512–1K（沿用 `*_low.glb` 文件名，查看器已按设备选档，`map/props/viewer3d.html` 的 `TIER`）。现在很多地标只有 0.5–1 MB，是太糙而不是太大。每个模型在查看器里按白天和夜里各看一次再发布。
- **B4 地标夜景烘焙**：每个有窗或灯具的地标烘一张发光贴图（窗、门灯、招牌、路灯头），查看器夜里（与地图同一时段）打开；没有灯具的地方不加光。和 B3 同一遍处理（先 B3 再 B4，同一批模型）。
- **B5 庄园剖切材质**：「楼层」视图（ESTATE-MODES-1 改名后的剖切）里的室内换成真实材质（按 `docs/eden-estate.md` 各房间的地 / 墙 / 顶写法），烘环境光遮蔽，加房间里真实存在的灯具（吊灯、壁灯、台灯，按 `eden-estate.md` 的灯光条目）作为夜里的光源。不碰伊甸 r6 的外观精修（用户暂停中）。
- **B6 伊甸分时段插图、地点图 8000 px**：伊甸高清插图跟随斜视主图，用同一相机对伊甸的投影包围盒裁切、两倍像素密度渲四个时段（插图相机文件同朝向）；俯视插图只保留白天，夜里不切白天插图（A1，FOG-1）。九张开局地点地图从 4000 px 重渲到 8000 px（仍是俯视地形图）。
- **B7 世界图**：全分辨率细边界、城市光斑、夜图（§0.5）。

### 0.8 渲染自检（没有用户审图）

渲染线按下面的规则自查，过了就登记（memory「no-user-review-renders」）。每条都写进该条目的 verify 记录。

1. **对位**：同一层各时段的图逐像素同框（相机文件哈希相同）；上层岛图叠在中层图上，岛的投影多边形（meta `poly_uv`）与成图 alpha 的包围盒偏差 ≤ 4 px。
2. **夜里没有无源亮斑**：夜图里亮度 > 0.6 的连通区域，必须在发光通道（Emit pass）或灯光对象里找得到来源；云、雾、地面上找不到来源的亮斑一律算失败。
3. **中层夜景全网格亮**：把中层夜图按 250 m 切格，除公园、运河、空地外，至少 80 % 的格子里有 ≥ 2 % 的像素亮度 > 0.5。
4. **中层白天比上层暗**：中层昼图街面中位亮度 ≤ 上层昼图岛面中位亮度的 0.6；霓虹在昼图里可辨（品红、青色像素存在于商业区格子）。
5. **下层无天光**：关掉所有灯和发光材质再渲一张 512 px 暗检图，除白班的 7 号井光柱外全黑（平均亮度 < 0.01）。
6. **上层夜景有灯**：每座岛在夜图里都能找到窗灯和停靠信标；伊甸没有结界边。
7. **曝光**：Standard 映射；高光溢出（通道 = 1.0）的像素 < 0.5 %，且只在灯头上。
8. 先出 2000 px / 16 spp 草图，自检过了再出 Mac 定稿；不在云端迭代（简报 §6）。

## 1. 可参考的同类背景

天城的骨架是「浮空岛 + 多层城市 + 阶级按高度分层」，外加「下层无光、层间设检查点、资源和人往上走」。下面几部作品的空间组织最接近，可以借来检验我们的地图是否可信。

| 作品 | 结构 | 对天城有用的地方 |
|---|---|---|
| 《最终幻想 VII》米德加（Midgar） | 离地约 50 m 的圆形上层钢板，由中央主柱加各区支柱撑起。板下是终年无光的贫民窟，按区编号（第 7 区），靠列车和板间通道连接。 | 与中层 / 下层几乎同构：支柱按网格分布；板下只有人造光；**层间通道是少数几个固定点，并且会聚成黑市和帮派据点**（7 号井 ≈ 七番街）。 |

## 2. 真实感从哪来（按作用大小排序）

1. **尺度统一，处处可以量。** 1 单位 = 100 m，片区 3 km × 1.875 km，街区格 24 m，支柱间距约 300 m，楼高按真实层高折算。地图可信，主要靠任意两处之间的距离说得通，细节多少是次要的。斜视用正交投影，这条在斜视里同样成立（§0.2）。
2. **光服从遮挡关系。** 现行规则见 §0.4。
   - ~~上层：白天直射光。~~ （D41 删除：上层四时段，夜里有真实灯光，§0.4）
   - ~~中层（夜景）：没有日照，浮岛挡住的是上方漫射下来的天光，所以影子在岛的正下方、边缘很虚（三层渐隐的暗面，不描边）。白天的中层远景（上层底图里）才按三层共用的太阳方向（`tc.SUN_ROT`）投影。~~ （D41 删除：中层昼 / 昏 / 夜三张，霓虹昼夜都开，夜里全网格亮，§0.4；岛下虚暗区保留）
   - ~~下层：几乎没有天光，光源只有钠灯、厂房、黑市。唯一漏下来的天光落在 7 号井的竖井口（已实现：冷色面光）。~~ （D41 删除：下层一个人造光体系，白班 / 夜班两张，§0.4）
   - 色彩映射一律用 Standard，宁暗勿曝。夜景的「真」来自光晕（Fog Glow）和溢光，不来自提亮。
3. **基础设施有流向。** 货运铁路、管廊、货梯都指向竖井和支柱（物资向上），排水、垃圾、废热往下。每条线都要能回答「从哪来、到哪去」。
4. **地价梯度决定密度。**
   - 离核心区和交通节点越近，楼越高、霓虹越密。
   - 下层的贫民窟挤在支柱之间的背阴处，厂房沿铁路分布。
   - 检查点和黑市周围最拥挤。
5. **交通分层。** 上层是空中航线加停靠平台；中层是悬浮轨道加主干道和连廊；下层是老旧地面铁路加步行窄巷。每层用自己的交通「语言」，一眼就能看出是哪一层。
6. **三层严格对位。** 同一随机种子生成同一张街道网。检查点和 7 号井、浮岛和它的投影在平面上重合，由 `tools/check_maps.py` 自动检查。斜视里对位改由相机文件保证（§0.6）。
7. **美术只来自渲染，交互只来自代码。** 标记、结界、投影轮廓、航线都是查看器里可开关的叠加层，不烘进底图。

city, R = layer.city, layer.rng                   # 城市布局（三层共用）与本层自己的随机
...                                               # 建本层内容：tc.box_mesh 批量盒子、tc.Batch 小图元
layer.marker('checkpoint_c', (x, y, 0), r=.6)     # 登记地标：平面坐标 + 占地半径（斜视时同时记 z，见附录 OBLIQUE-CODE）
layer.finish(world=(颜色, 强度), glare_opts={...})  # 相机 → 导出 map/data/tc_mid.json → 渲染

城区多边形与偏移在 `tc_city.DISTRICTS`。交界处铺一条林荫大道（两侧城区的路都接到它上面），楼从交界往里 75 m 内密度渐变，看不出拼缝；压在车行道中线上的「楼」（OSM 里偶尔有的地下通道、高架关系）自动去掉。缺高度的楼按城区补：商业区、核心区按城区强度，外围与城中村按低层。

规则：
- **城市（OSM）载入必须是第一个随机调用**（缺高度的楼、屋顶颜色按这个序列补），由 `Layer` 保证。各层只能在生成之后按 `kind` 重新配色、压低或删除（`tc.keep_mask`），不能再消耗城市的随机序列。
- 上层不另起种子（`seed=None`），岛屿沿用旧的随机序列，所以布局与 v0.7.0 逐字节一致。中层、下层各自另起种子。
- 外圈（§0.5）用同一套城市生成器，另起种子、低细节（不加楼顶部件、不加车流），中心柱范围内不生成。

### 导出格式 `map/data/tc_<层>.json`

```json
{ "extent_m": [3000, 1875], "layer": "tc_mid",
  "markers": [{ "id": "checkpoint_c", "nx": 0.6533, "ny": 0.868, "r": 0.02 }],
  "islands": [{ "id": "eden", "nx": 0.55, "ny": 0.4573, "rx": 0.0552, "ry": 0.0662, "rot": 0, "alt_m": 1150 }] }
```

`nx` / `ny` 是俯视底图的归一化坐标（左上原点）；`r`、`rx` 按图宽归一化，`ry` 按图高归一化。`islands` 只有上层有。D41 起每个标记另加 `z_m`（锚点海拔，米），斜视投影用；没有 `z_m` 的标记按本层参考高度（附录 OBLIQUE-CODE §B）。

### 注册表 `map/data/maps.json`（每张地图）

`title`、`parent`、`group`、`layer{name, sub, alt}`、`kind`（world / points）、`base`（DZI）、`data`、`focus`、`status: planned`、`alt{label, base}`（另一版底图，查看器里一个开关）、`periods{day, night, …}`（多时段底图：键是时段档位 dawn / day / dusk / night，值是该档的 DZI；查看器按世界时钟自动换，没配的档位 / 读不到世界时间 / 关掉时段色调开关时用 `base`；已配的昼 / 夜档不再叠色调，免得双重变暗）、`credit`（数据署名）、`overlay{type: dzi | barriers, label, src?, from?}`、`markers{id: {name, sub, cls, tag: set | inf, src, alias[], link?}}`。D41 起加 `views`（斜视 / 俯视两套底图与相机文件），字段见附录 OBLIQUE-CODE §A。

- `overlay.from`：叠加层取另一张地图的数据。中层的「上层投影」就是取上层的 `islands`。
- `link: {map, marker, label}`：跨层通道。地点卡里给一个直达链接，打开目标地图后聚焦并展开对应地点。`check_maps.py` 会检查两端在平面上是否重合。
- `districts[]`（points 地图，可选）：这一层的大区叫法（中英），当前地点只写到大区（「商业区」「地基区」）时落到这一层。
- `rooms[]` / `rooms_en[]`、`areas[]` / `areas_en[]`（kind=estate，可选）：庄园房间与室外区域的叫法；`alias` 里其余的词算「整座庄园」。

### 当前地点 → 自动落点（`map/app/here-v2.mjs`，单测 `node tests/here.test.mjs`）

地图总是先开世界图（maps.json `start = world`；首次打开和每次冷启动都是），收到 `eden-map:here` 只更新高亮与标题栏，不自动跳转；工具栏「当前位置」按钮（认得出当前地点时才显示）点了才跳过去。休眠后唤醒回到离开时的那张图与视野。事件横条不再在打开时自动飞向最新未读，点了事件才飞。单独打开查看器时可用 `?here=主卧` 或改「当前地点」输入框（回车）模拟。

| 级 | 当前地点写到 | 落点 |
|---|---|---|
| 1 | 庄园房间（主卧、书房、Master Bedroom …） | `eden_estate`，庄园页按 `estate:room` 切到该层并高亮房间 |
| 2 | 庄园室外区域（前庭、玫瑰园 …）或只写「伊甸庄园 / 庄园」 | `eden_estate` 外观，同一条 `estate:room`（庄园页的区域也认名字，自动切到外观） |
| 3 | 天城地标（执法局、7 号井 …） | 所在层，聚焦并展开地点卡 |
| 4 | 只有层名或大区（中层、地基区、商业区 …） | 该层，`view.focus` 默认视野 |
| 5 | 只有「天城」/ 世界地名 | 天城最上面一层默认视野 / 世界图聚焦该地点 |
| 6 | 匹配不到 | 不跳 |

各级取「当前地点包含的最长词」，中文原样、英文不分大小写。写了庄园以外的层或地标（「中层公寓客厅」）时，房间词不算庄园；比「庄园」更长的别处地标（如以后的「财团家族庄园」）优先。层切换器的红点按同一结果（1–4 级）落在对应层，庄园里的任何地方红点都在「伊甸庄园」。

### 加一个地标的流程

1. 在层脚本里建模型，调用 `layer.marker(id, 位置, 半径)`。

## 5. 性能

**渲染**
- 城市约 5.7 万个盒子用 numpy 一次建成一张网格，生成加建网格约 2 秒。
- 小图元（树、储罐、灯头）写进同一张 bmesh，避免上千个 bpy 物体。
- 夜景层 `bounces=4`：光主要来自近处的灯，少几次反弹看不出差别，渲染明显更快。
- 开了自动分块（2048），8000px 时内存不随分辨率平方增长。
- 点光按颜色共用灯光数据块。
- 云端 CPU 实测（2000px，16 采样，4 核）：
  - 中层 285 秒 → 228 秒（反弹次数从 12 次降到 4 次）。
  - 下层约 690 秒，改反弹次数后基本没变：下层的成本主要在约 4000 盏点光的采样上。下一步是把一部分路灯换成只有发光灯头、不投光的版本，或者按距离合并成少量较强的光源。
  - 上层约 60 秒。
- 斜视（D41）：正交相机下看得见立面，楼体侧面的材质和窗灯都要建；中层夜景的窗灯用发光贴图（按楼随机开灯），不用点光，避免像下层那样被几千盏灯拖慢。

- 清晰度档位限制最高层级。

## 附录 OBLIQUE-CODE：斜视标记投影与视图切换（给后续 Sonnet 提示词的步骤规格）

**目标**：查看器能显示斜视底图（三层），所有叠加物从地图米投影到斜视像素；俯视是开关；上层视图做 D40 合成。纯代码与数据步，不渲染。**前置**：FOG-1（D40 合成的图层顺序与遮罩、雾色 token）已合入；斜视底图可以先用批 1 的草图或测试夹具（`tests/fixtures/oblique/`）开发，正式底图到了只改 `maps.json`。

### A. 数据：`maps.json` 每层的 `views`

```json
"tc_mid": {
  "views": {
    "default": "oblique",
    "oblique": {
      "periods": { "dawn": "art/tc_mid_obl_dusk.dzi", "day": "art/tc_mid_obl_day.dzi",
                   "dusk": "art/tc_mid_obl_dusk.dzi", "night": "art/tc_mid_obl_night.dzi" },
      "cam": "data/cam/tc_mid_obl.json",
      "z_ref_m": 50,
      "outskirts": { "periods": { "...": "art/tc_mid_out_<period>.dzi" }, "cam": "data/cam/tc_mid_out.json" },
      "insets": [ { "id": "eden_hi", "marker": "eden", "periods": { "...": "..." }, "cam": "data/cam/tc_upper_eden.json" } ]
    },
    "top": { "periods": { "...": "现有俯视 DZI" }, "insets": "现有 insets" }
  }
}
```

- 没有 `views` 的地图行为不变（俯视，`base` / `periods` / `insets` 照旧）。有 `views` 时，现有的 `base` / `periods` / `insets` 视为 `views.top` 的简写，迁移脚本把它们挪进去（`tools/` 里一次性脚本，测试钉住）。
- 下层：`periods` 的 dawn / day → 白班图，dusk / night → 夜班图；俯视 `periods` 只留 night 一张（四个键都指向它）。中层：dawn 指向昏图。
- 上层 `views.oblique` 另有 `"composite": { "below": "tc_mid", "haze": "period" }`：下方取中层同时段的斜视图（D40）。
- 内核契约：`views` 是包数据（kernel-schema 加一行 K-R 编号，中英两版）；引擎里不出现层名。

### B. 相机文件与投影公式

相机文件（`map/data/cam/<name>.json`，由渲染 meta 生成，唯一来源）：

```json
{ "proj": "ortho", "az_deg": 165, "pitch_deg": 35, "m_per_px": 0.44,
  "right": [0.9659, 0.2588, 0], "up": [-0.1485, 0.554, 0.8192], "fwd": [-0.212, 0.7912, -0.5736],
  "frame": { "centre_m": [cx, cy, cz], "w_m": 3520, "h_m": 2200, "px": [8000, 5000] },
  "map_m": { "origin": "column-centre", "x": "east", "y": "north" },
  "hash": "<相机与画框的哈希>" }
```

- **地图米**：原点在中心柱中心，x 向东、y 向北、z 为海拔（米）。俯视归一化坐标换算：`X = (nx − 0.5) · 3000`，`Y = (0.5 − ny) · 1875`。
- **锚点海拔 z**：标记有 `z_m` 用 `z_m`；否则用本层 `z_ref_m`（下层 0，中层 50，上层取该岛 `alt + anchor_dz_m`，`upper_depth.json`）。地下设施按地面 0 投影，标记上加「地下」字形（引擎通用的 `below` 标志，包数据给）。
- **投影**（p 为地图米三维点，c = `frame.centre_m`）：
  `u = 0.5 + dot(p − c, right) / w_m`，`v = 0.5 − dot(p − c, up) / h_m`（画框归一化，左上原点；乘 `px` 得像素）。
  等价的 2 × 4 仿射矩阵 `A`（加载时由相机文件算一次缓存）：`[u, v]ᵀ = A · [X, Y, Z, 1]ᵀ`。
- **反算**（点击、编辑模式放置、路线点选）：屏幕点 (u, v) → 与平面 z = z₀ 求交，z₀ 默认本层 `z_ref_m`。正交下视线方向恒为 `fwd`，闭式解：先由 u、v 得到画框平面上的点 `q = c + (u − 0.5) · w_m · right − (v − 0.5) · h_m · up`，再 `p = q + t · fwd`，`t = (z₀ − q_z) / fwd_z`。
- 实现：`map/core/project.mjs` 加正交分支 `projectOrtho(p, cam)`、`unprojectOrtho(u, v, cam, z0)`、`affineOf(cam)`；`blender/project.py` 同一规格；`tests/fixtures/project_golden.json` 增加正交用例，两边对拍（进 smoke）。透视分支保留给预览。

### C. 叠加物怎么投影

| 叠加物 | 斜视做法 |
|---|---|
| 地点图钉、标签、人物头像、事件标记 | 锚点 (X, Y, z) → (u, v)；仍在屏幕空间绘制，大小不随底图缩放 |
| 路线、悬浮轨道、交通线、巡逻线 | 每个顶点按自身 z 投影（地面线用 `z_ref_m`，高架线用数据里的 z）；正交下直线仍是直线，不用细分 |
| 区划、结界、雾区、危险区等多边形 | 顶点按 `z_ref_m`（或多边形自带的 z）投影；多边形仍是多边形 |
| 浮岛轮廓（中层的「上层投影」叠加层） | 斜视里关闭：上层视图已合成，中层视图不再画上层岛的投影 |
| 上层岛的遮挡 | 读 meta 的 `visible_ratio` / `label`（normal / lift / dot），沿用 `labelRule`；中层、下层的图钉总在最上层，不做遮挡 |

### D. 点击命中

- 图钉、标签、头像：屏幕空间命中（现有做法），位置换成投影后的 (u, v)。
- 多边形：把点击点反算到该多边形所在的 z 平面，在地图米里做点在多边形内的判断（不在像素里判断）。
- 上层岛：先按 meta `poly_uv` 在像素里判断，命中多座时取 `depth` 最小（最近）的一座。

### E. 俯视开关

- 图层菜单加一个「俯视」开关（存储键 `edenMapTopView`，默认 0，登记在 `map/core/storage.mjs`、protocol SCHEMA、中英文字）。开 = 用 `views.top`；关 = `views.default`。
- 切换时保持视野：取当前视野中心，反算到地图米（z = `z_ref_m`），在新视图里投影回去作为中心；缩放按「每屏幕像素多少米」（东西向）保持不变。
- 俯视里叠加物用现有的 nx / ny 路径，不经相机文件。

### F. 合成与分层切换

- 同一组里各层斜视图同朝向、同 `m_per_px`，所以图像 B 放进图像 A 的坐标系只是平移：B 的左上角在 A 的归一化坐标里是
  `x = 0.5 + dot(c_B − c_A, right) / w_A − w_B / (2 w_A)`，`y = h_A / (2 w_A) − dot(c_B − c_A, up) / w_A − h_B / (2 w_A)`（OpenSeadragon 世界坐标以 A 的宽为 1，A 的高是 `h_A / w_A`），宽 = `w_B / w_A`。外圈图、插图、上层视图下方的中层图都用这一条放置。
- 上层视图的图层顺序（D40）：中层外圈 → 中层斜视图（当前时段）→ 高空霾（FOG-1 雾色 token，按时段；「显示下方城市」关时加厚到近乎不透明）→ 上层岛图（alpha）→ 叠加物。
- 换层（上层 ↔ 中层 ↔ 下层）：保持视野中心的 (X, Y)，在新层按其 `z_ref_m` 投影，平移视野；缩放保持米 / 屏幕像素。
- 同一层换时段：只换瓦片源，相机文件不变（check_maps 保证）。
