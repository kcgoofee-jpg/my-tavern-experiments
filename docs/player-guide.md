# Player guide (REL-DOCS, B3)

Status: 2026-10-06. The edition players read is `docs/player-guide.zh.md` (D18: Chinese is canonical until the repository
split); this English file is the structural original and both are kept heading-for-heading by `tools/check_zh_mirror.py`.

## What this is

- A map layer that runs inside your chat: a floating button opens a world map, city maps and 3-D pages.
- It ships as exactly two things: the imported script and an add-on worldbook. It never generates a character card and
  never edits one; it never writes the card's own variables.
- Everything it shows is recomputed from the chat floors. If the text says nobody went anywhere, the map does not move
  anybody.

## Install

1. In TavernHelper, create a script with this single line:
   `import 'https://cdn.jsdelivr.net/gh/kcgoofee-jpg/my-tavern-experiments@map-v0.9.8/map/tavern/eden-map.js'`
2. That address is pinned to a release tag; it does not drift. Refresh the tavern and open a card that has a map.
3. To follow development instead, import the script generated by
   `python3 tools/build_preview_script.py --follow preview`. It re-pins itself to the newest commit every time you open
   the map.
4. Install one of the two, not both: two live copies fight over the same floating button.

## First opening

- The floating button opens the panel; the first frame is the region the story is currently in.
- The title bar holds: layer and view switching, the ⇄ line button, language, settings and 反馈 (feedback).
- Breadcrumb at the top: world → city → district → building. Double-click a marked place to fly to it; a place with a 3-D
  page offers 「进入」.
- The first open downloads the base maps once; afterwards the browser cache and the map's own preload make it fast.

## What the map reads, and how to correct it

- It reads the chat text: place tags, character positions, events, items and the card's own MVU variables when it has them.
- Without a TavernHelper-capable host the map still draws, but nothing is injected into the prompt and the state line stays
  off — it says so in the self-check instead of failing silently.
- If the map has the wrong idea, write one of these in your next message and it re-reads:
  `（OOC 地图：现在在 某处）` and `（OOC 地图：某人 在 某处）`.
- Settings → the AI link page has a 「提醒 AI」 block with four templates (place, people, event, items). Tapping one fills
  your input box and never sends it.

## When it is slow or blank

- Three delivery lines are tried automatically and the fastest one that answers is kept for 24 hours; only the host changes,
  the content is identical.
- A line that stalls for 10 s is skipped. If the viewer document comes up but sends nothing for 15 s, the boot watchdog
  remounts it once on the same address and then walks up to three alternate lines, and says which one it took.
- All tiles failing switches the line once by itself (one switch per two minutes).
- You can pick a line by hand with ⇄. A hand-picked line is kept until you clear the choice — the map then stops measuring.
- Slow devices and save-data mode drop to the lighter tier by themselves; the tier can be set in settings.

## Privacy and safety

- The AI advisor key is stored in this browser's local settings, and any script running on the same page can read it. Put a
  key there only if you accept that; the notice sits next to the field.
- The feedback report contains the map version, the self-check results, current placement and the map's own log. No chat
  text, no card text.
- The map writes only into its own storage (the pack's chat variable and its own worldbook entries, marked as ours). Your
  own worldbook entries are never touched.

## Content rating

- The Eden pack is 18+. The rating is declared by the pack and shown in settings and in the credits; the engine does not
  know any card's content boundaries, filters nothing and moderates nothing. It reads and places what the story says.
- The original character card is by Yehehua; the pack credits name them and the release keeps that credit visible.

## Feedback

- The 反馈 button in the panel previews the report, copies it, downloads it, and opens a pre-filled GitHub issue.
- GitHub issue forms: `Bug report` and `Feature request` in the repository. Say which host and version (ST 1.19.0 /
  TavernHelper 4.11.2 / TauriTavern 2.3.0), which delivery line, and which step failed.
- Unverified ground is listed in `docs/compatibility.md` §8 — phone TauriTavern among them. A report from one is worth more
  than a guess here.

## Not supported

- No character card is produced or modified; the deliverables are the script and the worldbook add-on.
- No phone-specific tuning, and no promise about phone hosts.
- No npm package: the map is served from the repository, and the npm route in the code is a sealed fallback that is never
  published.
