# 性能评估 · 低端安卓（3 GB 内存、慢 CPU、弱 3G/4G、没梯子走 jsdmirror）

## 1 测了什么、看了什么
这次只做了静态测量：没有跑 Playwright，没上真机，也没在真实网络下测，所以下面没有任何耗时实测值。

- 文件体积（原始大小 / gzip -9 压缩后，用来近似 CDN 压缩后的大小）：viewer.html 149.5K / 51.4K；openseadragon.min.js 277K / 66K；events.js 41K / 16K；section.js 42K / 12.5K；chars.js 11.7K / 5K；eden-map.js 52.7K / 18.7K；maps.json 17K / 6K；tc_upper.json 60K / 9.7K。
  - 首次打开要下的程序和启动数据，压缩后合计约 170–180 KB。按 3G 有效带宽约 50 KB/s 估算，光传输就要 3.5 秒左右（这是估算，不是实测）。
- 瓦片（512px JPG）：
  - world：L11 共 12 张 196K，L12 共 40 张 540K，L13 共 160 张 1.48M
  - borders：L11 196K，L12 168K
  - tc_upper：L12 476K，L13 1.36M
  - 另外：云精灵 puff1–6.png 共约 310K；world_1k.jpg 120K。
- 省流模式判断：eden-map.js:220 和 viewer.html:512/516 都用同一组条件：deviceMemory ≤ 4、saveData、网络为 2g/3g。
  - 3 GB 的安卓 Chrome 会报 deviceMemory = 2 或 4，所以省流为真，这个人设下判断是对的。
  - 省流生效后的行为：
    - 不开后台预加载面板（幽灵面板）。
    - 不预热瓦片（viewer.html:680、729）。
    - 云不漂移，不请求任何精灵图（1537）。
    - 自动清晰度最高只到标准档（4000px）。
    - 低内存时关掉毛玻璃（27）。
    - 瓦片并发降到 6，缓存降到 30（610）。

## 2 发现（按严重程度）

### P0：无

### P1
1. **选线测速每次打开都重做，流量翻倍，慢的那路也不取消**（eden-map.js:31-44）
   - probe 同时向所有线路请求 maps.json（cache:'no-store'，原始 17K / 压缩后 6K）。Promise.any 拿到第一个结果后，没有取消另一路，它会继续下完。
   - 每次切换或打开聊天都重新测一遍；只有手动选过线路才会跳过。
   - 弱网下这些请求会和首屏抢带宽。jsDelivr 在国内经常要等满 6 秒超时，这 6 秒里一直占着一个连接。
   - 修法：测速改取 data/build.json（46B）；赢家出来后 abort 其余请求；结果连同时间戳存进 localStorage，24 小时内不再测，失败了才重测。约 0.5 小时。
2. **viewer.html 每次打开都整页重新解析**（eden-map.js:272-295）
   - 150K 的 viewer.html 先按文本取回，再用 srcdoc 注入，iframe 不能边下边解析。
   - 里面大段内联 CSS 和 JS，每次打开都要在慢 CPU 上整体重新解析。内联脚本也用不上 V8 的代码缓存。
   - 修法：把内联主脚本（大约 475–1520 行）拆成外链的 viewer.js，走 CDN、HTTP 缓存和 V8 代码缓存；srcdoc 里只留骨架。约 2–3 小时，改完要在 TT 上回归。

### P2
3. **OpenSeadragon 整包加载**（viewer.html:101）
   - 277K（压缩后 66K）用 defer 整包加载。慢 CPU 上解析它估计是首次打开最大的 JS 开销，但没实测。
   - 不改代码能做的：确认 jsdmirror 返回 br/gzip 压缩和长缓存头（路径带版本号，本来就可以设成 immutable）。
   - 自己裁一个精简版收益不大、工作量大，建议先不做。
4. **省流模式下仍预取庄园页 HTML**（viewer.html:731）
   - warmOthers 在省流时还是会取庄园页的 HTML 文本。
   - 省流时这一步应该跳过：按 1346 行，省流下庄园反正会被替身地图换掉。约 0.2 小时。
5. **每秒一次的定时器从不停止**（viewer.html:1007）
   - 这个 setInterval 永不清除。地图休眠或隐藏时仍每秒唤醒一次、遍历所有图层，低端机会费电。
   - 修法：只在有瓦片正在加载时启动；面板隐藏时 clearInterval。约 0.5 小时。
6. **放大后两套瓦片叠加**
   - 标准档放大到 L12 时，world 和 borders 两套瓦片同时加载，合计约 700K。borders 的 .dzi 格式（PNG 还是 JPG）没有逐个核对。
   - 建议：省流时边界层最高只到 L11，或者改成矢量 / 单张低清图。约 1–2 小时。

### P3
7. **快速缩放时反复量尺寸**（viewer.html:1461 的 px()）
   - 双击后拖动缩放时，每次 pointermove 都调一次 getBoundingClientRect，会轻微强制重排。只在这个手势里触发，影响小。
   - 修法：在 pointerdown 时缓存一次尺寸。约 0.2 小时。
8. **顶栏布局逐个量宽度**（669 行 layoutHeader）
   - 用 offsetWidth / scrollWidth 逐个元素测量，但只在内容变化时通过 requestAnimationFrame 执行一次，影响小。
9. **触摸延迟：没有问题**
   - 单击没有 300 毫秒等待；1458-1480 行只在第二次按下时才判断是不是双击缩放。

## 3 性价比最高的 5 项
1. 选线测速改用小文件、取消慢的那路、结果缓存 24 小时（P1-1，0.5 小时）
2. 把 viewer.html 的内联脚本拆成外链，用上 HTTP 缓存和代码缓存（P1-2，2–3 小时）
3. 没有瓦片在加载或面板隐藏时，停掉每秒一次的定时器（P2-5，0.5 小时）
4. 省流时不预取庄园页 HTML（P2-4，0.2 小时）
5. 省流时边界层最高只到 L11（P2-6，1–2 小时）
