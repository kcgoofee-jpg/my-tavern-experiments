# C3 门控 · 交互与性能评审（独立评审，只看材料和代码，没开浏览器）

**评分：7.0 / 10**（v2 云端评审给 8）。缩放这一套已经做扎实：以光标为中心的滚轮、捏合、+ − 复位、双击、父页不滚、不用 VPN，实测全部通过。扣分在三处：手机第一帧超预算；近景「细节 ›」在手机上不顺手，桌面还有一处疑似点不到的 bug；自动降档的判据太敏感。

## 做得好的
- `zoomAt` 在缩放前后各 unproject 一次，差值同时加到相机和 target 上，光标下的点漂移 0 px（`?tier=0` 实测）。`keepTargetY` 把轴心拉回原来的高度，旋转中心不会跑偏。
- 滚轮这块考虑周全：`deltaMode` 归一，单次增量限在 ±150，`ctrlKey` 用另一套系数给触控板捏合，Safari 的 `gesture*` 单独处理。`window` 上的滚轮一律 `preventDefault`，`#app` 设 `touch-action:none`，`html/body` 设 `overscroll-behavior:none`。实测父页 `scrollY=0`。
- 触屏：双指捏合以两指中点为中心缩放；双指轻点拉近房间；自己判双击（300 ms / 30 px），单击延后 250 ms，两者不冲突；拖动时 DPR 降到 ×0.75，停下 150 ms 后恢复。
- 预算：首屏和全部传输都是 1.26 MB / 12 个请求（上限分别是 3 MB 和 15 MB）；pixelRatio 上限 [2, 1.5, 1]；CDN 请求为 0。首帧先跳过阴影、预编译着色器，背景建造按 12 ms 切片——v2 提的 1、4 两条都已落实。

## 明确回答
**(a) 用户能不能轻松看到清楚的马桶 / 毛巾近景？**
- **桌面：基本可以。**
  - 路径是「3F → 点主浴室 → 细节 ›」三次点击。马桶间（木座圈、柱式底座、高位水箱、拉链）看得很清楚；毛巾是程序生成的，能认出叠放和绣标，但质感一般。
  - 两个隐患：第二次点「细节」可能点不到（P1-2）；按 + / − 吊灯会回来（P1-1）。
- **手机：能到，但算不上轻松。**
  - 三个触控目标都偏小。
  - 近景里卡片一直盖住画面上方的 31%。
  - 被看的东西往卡片下面偏。
  - 毛巾有锯齿，只是勉强可读。
  - 马桶视点没有实拍证据。
  - 结论：没有达到用户说的「清楚」。

**(b) 本机 R02 / R11 修完后，嵌入模式有没有交互回归？**
- 修复本身没有带来新的回归：9 个楼层按钮、导览条的 3 个采样点都落在庄园上，父页 `scrollY=0`。
- 修完后仍然存在、或更显眼的问题：
  - 导览条盖住 − 和复位（P1-6，云端）。
  - 46 px 写死，也没留安全区（P2-3，本机）。
  - 那条 46 px 带子上的滚动串到宿主页，还没验证。

**手机第一帧 2.63 s 算 P0 还是 P1？** 算 **P0**。这是写明的门控预算，而且是在最有利的条件下（M5、无节流）超的；桌面与手机相差 2.5 倍，说明有具体的开销可以挖，不是硬件天花板。

**桌面在 headless 下自动降到 T2，对真实低端笔记本是不是风险？** **是（P1）。** 判据会被自己的阴影重画和着色器编译触发，而且只降不升。低端集显（UHD 620 这一档）大概率在第一次展开楼层时就掉到 T2，之后一直没有阴影，这是永久性的画质损失，本来没有必要。
