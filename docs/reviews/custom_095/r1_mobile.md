# 第 1 轮 · 手机单手 RP 玩家（v0.9.5「自定义」面板）

身份：右手拿手机（375–430 宽），左手端着杯子，边聊边改地名。只关心：拇指够不够得到、键盘会不会挡、会不会点一下就误跳。

**分数：7/10**

## 问题
1. **P1 选择器副标题显示原始宏 `{{user}} 的庄园`**
   证据：`shots/cu_phone_picker.jpg` 第一行「伊甸庄园」下写 `{{user}} 的庄园`；`map/tavern/picker.mjs` buildGroups 直接取 `v.sub`，不做宏替换。
   修法：选择器和搜索走查看器地点卡同一个 `{{user}}` 替换；拿不到用户名就去掉这段宏。补单测：sub 含 `{{user}}` 时输出不含 `{{`。
2. **P1 手机上一进选择器就自动聚焦搜索框，键盘弹起挡住约一半分组列表**
   证据：summary「焦点在搜索框」(phone 同样 foc:cuQ)；`cu_phone_picker.jpg` 搜索框在最顶。想点分组 chip 或滚动得先收键盘。
   修法：`(pointer:coarse)` 下焦点给标题（和列表页一样），搜索框不自动聚焦；桌面保持现状。
3. **P1 返回 / 关闭 / 保存都在屏幕上半部，拇指够不到**
   证据：`cu_phone_list.jpg`、`cu_iphone_edit.jpg` 返回与关闭在 y≈108/1200；保存在 y≈665，键盘弹起后更靠上。`map/custom.js` 383 行起的 @media 只把对话框铺满，没有底部操作栏。
   修法：≤640px 时「保存 / 取消」做成贴底 sticky 栏（含 `env(safe-area-inset-bottom)`），列表页「添加」也放底部；左边缘右滑 = 返回。
4. **P2 分组 chip 只写「1F / 2F」，看不出是庄园楼层**
   证据：`cu_phone_picker.jpg` chip 行「天城下层 | 1F | 2F…」；picker.mjs 房间组 `short: f.label`。
   修法：第一个庄园 chip 写「庄园 1F」，或加一个不可点的分隔标签「庄园」。
5. **P2 点卡片主体也会飞走，滚动时误触代价高**
   证据：`custom.js` listHtml 里 `.cu-main` 带 `data-fly`，与底部「在地图上看」重复；拇指按在卡片上滚动一松手就关面板跳地图。
   修法：卡片主体改为进编辑（或不响应），飞行只留一个明确按钮。

## 结论
主流程在手机上能走通、触控都 ≥44px，但宏外露和「键盘 + 顶部按钮」让单手用起来还不顺；修完 1–3 可到 8.5。
