# 第 1 轮 · 重度长线 RP 玩家（v0.9.5「自定义」面板）

身份：一个聊天跑了上千楼，几十项自定义，大部分是剧情标签（【改名】/【用途】）写进来的，偶尔手动修。只关心：数据稳不稳、项多了找不找得到、剧情和手动改动会不会打架。

**分数：6/10**

## 问题
1. **P1 剧情标签会静默覆盖手动改过的名字 / 用途**
   证据：`map/tavern/mvu.mjs` applyTags（约 184–194 行）对找到的项直接 `setCustom(..., { source:'tag' })`，不看原 `源` 是否「手动」；覆盖后徽章也从「手动」变成「剧情标签」，手动内容不留痕。
   修法：原 `源 === '手动'` 时，标签只记为「剧情建议」（卡片显示建议值 + 采用 / 忽略），或至少保留被覆盖的旧值并在 toast 里写明。补单测。
2. **P1 改名后旧显示名丢失，前面楼层里的叫法再也匹配不上**
   证据：`mvu.mjs` setCustom 里 `cur.名 = v` 直接替换，不把旧 `名` 放进 `别名`；aliasMap 只认 `名 + 别名`。「星图室」改成「观星阁」后，前几百楼写「星图室」的位置就找不到地点。
   修法：改名时把旧 `名` 推进 `别名`（去重，上限约 8 个），编辑页显示「旧叫法」可删。
3. **P1 列表没有搜索 / 筛选 / 排序，几十项只能一直滚**
   证据：`map/custom.js` listHtml（144 行起）按插入顺序全量输出，每张卡带 3 个按钮；`cu_phone_list.jpg` 一张卡约 190px，30 项约 5700px。选择器的 filterGroups 已能搜自定义名和用途，列表页没用上。
   修法：列表页顶部复用同一个搜索框；加「来源：全部 / 手动 / 剧情标签」「类：房间 / 地标 / 人物」筛选；按最近修改排序（需存时间戳）；超过 10 项时卡片折叠成单行。
4. **P2 重置不能撤销**
   证据：`custom.js` 217–218 行，第二下直接 `removeCustom`，只提示「已重置」。剧情积累的用途误删找不回。
   修法：删除后给 5 秒「撤销」，缓存被删条目。
5. **P2 世界书只有一个常驻条目，项多时长度不可见**
   证据：summary「一个常驻条目」；设置和卡片都不显示摘要当前长度。30 项 × 200 字 ≈ 6000 字常驻背景。
   修法：设置里显示「当前摘要约 N 字」，超阈值提示，并允许单项「不发给模型」。

## 结论
功能齐、校验严，但对「标签为主、项多、跑得久」的聊天，覆盖手动内容与改名丢旧叫法会悄悄破坏剧情连贯性，这两条修掉前不建议放给长线用户。
