# r1 重度 RP 玩家 审阅：6.5/10

1. **P1 位置过期**：`map/tavern/characters.mjs` collectChars。MVU 在场表里有这个人（src 推断）时，只要 80 楼窗口里有过他的旧标签，就 `continue` 保留旧标签位置。结果是同行者跟着玩家换了地方、模型又没补标签（规则里写了“同处不用写”），列表仍然显示几十楼前的地点。修法：只要 MVU 在场，就以“与你同处”为准；只有标签楼号 ≥ 玩家最近一次换地点的楼时，才让标签覆盖在场推断。
2. **P1 标签太老也照样显示**：tag 来源只写了“第 N 楼”，没有标出已经隔了多久。长线剧情里 70 楼前的位置和刚写的一样亮，注入摘要写的也是“最新已知”，模型会拿过期位置当事实。修法：隔了 >20 楼的淡显，并标“约 X 楼前”；注入摘要只放最近约 30 楼的标签（或给每人加楼龄），更老的不注入。
3. **P1 swipe 不回滚 ⌖改名/⌖用途**：`eden-map.js` customTags / `mvu.applyTags` 只处理比 tagFloor 新的楼。swipe 掉带标签的那一楼后，改名还留着；新 swipe 在同一楼号，里面的标签也不会被处理。只有删楼能回退 tagFloor。修法：记下每条标签应用时的楼号 + 原文哈希；MESSAGE_SWIPED/UPDATED 时如果该楼文本变了就撤销那一条，并重新扫这一楼。
4. **P2 注入重复**：同步世界书打开后，态势注入里的 `[地图自定义…]` 摘要和世界书条目内容重复，每轮白花约 50–100 tokens。修法：同步开着时不注入摘要（二选一）。另外人物位置摘要最多 8 人 × 每轮，建议只在内容变化后的几楼注入，或只放不在场的人。
5. **P2 规则措辞会让模型每楼写标签**：“地图人物位置 v1”要求“进入/离开/移动都写”，模型在群像场景下常常每楼都刷一堆标签，会挤占正文末尾。修法：再加一句“只在位置变化的那一楼写”。常驻规则已经 2614 tokens，可以考虑把人物位置规则并进联动规范，省去重复的格式说明。方位 EJS 只展开一条、约 81 tokens、描述中性，这部分没问题。夜色和标题时刻轻量不碍事，着装行有用，保留。

结论：方向对，时间、夜色、着装、方位注入都没打断沉浸；但长线剧情里人物位置会停在过期地点，swipe 也不会撤销改名，修好这两点再发。
