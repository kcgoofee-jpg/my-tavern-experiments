# MVU 0.9.3 R1 — 现编审阅者
**身份**：同时开三四个聊天（同一张卡、不同存档分支）来回切换的玩家，本职是做前端数据同步的工程师，桌面 Chrome。
**为什么选他**：本轮把自定义数据从 localStorage 搬到聊天变量 `eden_map`，加了旧键迁移和「同步世界书」（一个全局名字的世界书 + 自动绑定聊天）。两位固定审阅者只看单聊天的剧情和卡结构，看不到多聊天和切换时序的问题。
**只看**：换聊天时的数据归属、迁移是否重复执行、同步世界书的跨聊天副作用、写入竞态、自定义文字进 innerHTML 的路径。**不看**：注入文案、MVU 结构、画面。
证据：读 `map/tavern/eden-map.js` 447–532、`map/custom.js` 45/86；`node tests/mvu.test.mjs` 10 项通过（但没有多聊天用例）。

## 分数 6/10

1. **P1 同步世界书会串到别的聊天** — `eden-map.js` syncWb：所有聊天共用一个世界书名 `伊甸地图·自定义`，`createOrReplaceWorldbook` 整本覆盖。聊天 A 打开同步后已绑定；到聊天 B 打开同步，内容换成 B 的，A 下一轮就注入 B 的叫法和用途。修法：世界书名带聊天 id（如 `伊甸地图·自定义·<chatId前8位>`），或每个聊天一个条目并靠绑定区分；UI 写清楚是「每个聊天一本」。验收：A、B 两个聊天各设不同叫法，都开同步，切回 A 看世界书内容仍是 A 的。
2. **P1 换聊天时可能写错聊天** — `loadCustom`：先 `await migrateOld()` 再 `await saveRoot()`，`customChat !== id` 的检查放在保存之后；`writeVars` 在写入那一刻按当前聊天写 `getVariables({type:'chat'})`。迁移期间切换聊天，旧聊天的 custom 会写进新聊天。`customChanged` 里 `saveRoot()` 也没 await，api.setCustom 与 CHAT_CHANGED 同时发生时同样可能写错。修法：写入前比对 `chatId() === customChat`，不一致就放弃；CHAT_CHANGED 时让进行中的写入失效（用代数 token）。验收：加一个测试，模拟 migrateOld 期间 chatId 改变，断言新聊天变量没被写。
3. **P1 全局旧键每个聊天都会重新迁移** — `migrateOld`：`H.customKey('')`（全局 `edenMap:custom`）迁完不改名，所以每打开一个聊天都会并入一次，包括全新聊天；用户在某聊天里「重置」某项后，重新加载又被并回来。修法：全局键迁移后记一个标记（如 `edenMap:custom.migratedTo=<chatIds>`，或只在第一次迁移的聊天里并入），并且只在 `eden_map` 为空时迁移。验收：重置一项后刷新，该项不再出现；新开聊天不带旧全局叫法（或文档说明是有意的）。
4. **P2 自动改绑聊天世界书没有提示** — 当前聊天没有聊天世界书时，`rebindChatWorldbook` 会静默绑定；关掉同步后不解绑、也不删世界书，而条目仍为常驻，旧叫法会继续注入。修法：关同步时把条目 `enabled:false`（或解绑自己绑的那本），绑定时在设置里提示一次。验收：关同步后本轮提示词里不再出现自定义条目。
5. **P2 XSS 目前没问题但缺回归测试** — `custom.js` 45/86 与 `chars.js` 都 esc 或 textNode，标签 ⌖改名 的内容（来自模型输出）也走这些路径。修法：`mvu093.mjs` 加一项：名字 / 用途为 `<img src=x onerror=...>` 时列表、地点卡、提示条都只显示文字。

**结论**：单聊天路径做得扎实，但「按聊天存」的承诺在多聊天切换、全局旧键迁移、共用世界书三处都有漏洞，修好 1–3 前不建议发布。
