# E5 第 2 轮 · 桌面剧情玩家（RP）审阅

审阅人设：桌面上长时间跑剧情的玩家。地图面板开着，边聊边看。
被测：分支 `cloud/tc-mid-low`，HEAD `3f9ba38`（工作区里另有 Blender / 数据改动，不涉及查看器）。

## 1. 环境

| 项 | 值 |
|---|---|
| 机器 | Mac17,3（Apple M5），macOS |
| 浏览器 | Playwright Chromium（`tools/browser/lib.mjs`，desktop preset），DPR 1 |
| 视口 | 1440×900（主测，中 / 深）、1280×800（中 / 深）、900×650（EN / 浅） |

| 宿主 | 自写的酒馆模拟页：路由出来的 `__rphost.html` 加 `__rpscript.html`。它模拟 `getChatMessages`、`getLastMessageId`、`MESSAGE_RECEIVED`、MVU `fireUpdate`、`injectPrompts`，加载的是仓库里真实的 `map/tavern/eden-map.js`。输入框固定在底部，位置和酒馆一样 |

每次运行都通过 `lockrun.sh` 拿锁，同一时间只开一个浏览器，每次运行不超过 3 分钟。

## 2. 总分：**7.5 / 10**（E4b 同人设 7.5 → E5 r2 7.5）

| 分项 | 分 | 理由 |
|---|---|---|
| 地点联动 | 8 | 换地点后能跳到对应层并开地标卡。层按钮的「在这层」红点、宿主标题栏的「当前地点：莉娅书房」（`{{user}}` 已替换）都对。庄园里从书房换到主卧，房间卡会跟着换。扣分：认不出的地点没有任何提示（L3）；同一楼既换地点又出事件时，事件飞行会盖掉地点跳转。 |
| 事件叙事 | 8.5 | 列表条目有楼层号、发布方、「已解除」状态和「新」标记。天城外的事件能落到世界图。卡片字段网格清楚，也显示「聊天第 N 楼起，更新 1 次」。新事态和花屏的播报合成一句（R09 已修）。 |
| 跨层飞行 | 8.5 | 从列表用键盘 Enter 可以跨层飞到事件并开卡，焦点落在 `#cardTitle`（R06 已修）。落地时卡片和横条都没有盖住事件点（0 / 2）。卡内跨层链接用键盘也能跳，焦点同样正确。Shift+PageDown 能离开庄园。 |
| 干扰程度 | **6** | 边打字边推 40 楼：宿主输入框没丢焦点，40 个字 0 丢失，这点好。但**面板开着时，每来一条新事件地图就被拉走一次**：40 楼里换图 21 次，玩家正在看的卡片被关掉。面板是居中的 94vw×88vh 大浮层，聊天正文被整块挡住，没法真的「开在侧边」。 |
| 长时间稳定 | 9 | 40 楼加 8 次关开面板（休眠 / 唤醒）之后，强制 GC 后堆 5.0 → 6.6 MB，DOM 节点 630 → 779，JSEventListeners 359 → 392。事态叠加层始终在 8–25 个之间；控制台 0 错误，没有 4xx。 |

## 5. 关键数字

- 开面板到底图画出：347–485 ms（预加载后的热缓存）。
- 切层（PageUp / PageDown，有 Blender 在渲）：0.9–2.6 s；进庄园 10.1 s。
- 40 楼流式推送：
  - 宿主输入框焦点从未丢失（0 / 40 楼）。
  - 打字完整（40 / 40）。
  - 地图 `cur` 变了 21 次（RP-1）。
- 稳定性：DOM 250–414，叠加层 8–25，GC 后堆 6.6 MB，0 错误。

## 6. 一句话结论

E5 把本人设关心的键盘、焦点、播报、死区和工具栏问题都修干净了，40 楼长跑也很稳。但面板开着时，每条新事件都会把地图拉走、关掉正在看的卡片，加上面板是居中大浮层，「边聊边看」这个核心场景仍然被打断，所以停在 7.5，没过 8 分门槛。
