## 3. 冲突裁定

- **R06 飞行后焦点**
  - 分歧：手机报 ⚠（焦点落到 BODY / DIV）；RP、无障碍报 ✅（焦点落到 `#cardTitle`）。
  - 裁定：两边都对，测的路径不同。键盘 Enter 这条路径已修好。触屏点击后焦点落到 body，对指针用户没有影响，降为 P3。「关卡后焦点回到触发元素」在触屏路径上也要做到，并入 F-05 一起修。
- **R10 嵌入先下世界瓦片**
  - 分歧：RP 报 ⚠（先下 4 张上层瓦片）；弱网、现编、无障碍都实测世界瓦片 0 张。
  - 裁定：R10 ✅。RP-9（先下上层 4 张）和 W5（地点晚到 1.5 s）记为 P3 遗留。
- **V16 / R15 工具栏一行**
  - 分歧：设计、RP 在 846–1440 宽下测到一行 ✅；无障碍在 641–860 × EN 下测到控件越界。
  - 裁定：采纳无障碍的结论。这不算矛盾，是宽度覆盖不同。F-01 定为 P1 回归。
- **W2 / W3 tokens.css 单点**
  - 分歧：弱网审阅各记为 P2。
  - 裁定：**升为 P1，合成一条**。理由：样式表挂起时独立页一直白屏；它也是弱网分数没到 8 的主要原因之一；修法很小。
- **P-01 不是本轮回归**
  - 手机审阅说这条在 E5 之前就存在。
  - 裁定：仍按 P0 计。门控看的是「现在有没有 P0」，不看是不是本轮引入的。
- **不采纳，记入后续版本**
  - RP-2 面板改成可停靠侧边：这是新功能，放到 E6 以后。
  - D7 工具栏缺少天城细节：观感问题，等 F 之后再说。
  - RP-3、RP-4、P-03、P-04、F-11、W4 的超时阈值、Era 未翻译：都归云端 / 冻结，放到 Blender 版庄园页再处理。
- **工作区已有未提交草改**（`map/tavern/eden-map.js`）：P-01 的 `minmax(0,1fr)` + `min-width:0`、RP-1 的 `flyNext`、EJS 剥离、`88dvh`、角标 tabular-nums、悬浮按钮 i18n。这些不在本轮审阅的代码里，不算已修；第 3 轮按下表的验收标准复测。

## 5. 轮次

- 这是第 2 轮，GOAL 规定最多 3 轮，**还剩 1 轮**。
- 第 3 轮只修上面的 P0 / P1，不加新功能。之后 6 位审阅者复跑，另外再现编 1 位新人设，重点测 TT WKWebView、blob iframe 和低内存。
- 如果第 3 轮仍然不过：取「P0 数最少、其次平均分最高」的版本进入 F 阶段，未过的 P1 和全部 P2 / P3 列入 CHANGELOG 的「已知问题」和 GOAL 的遗留。预计第 3 轮会是最佳版本。

## 6. 与 GOAL 原文的差异

- GOAL 的 E5 原文只要求「按 ui-audit 规范统一，再跑一遍 E4 的人设测试，对比前后分数」，没有分数门槛。「每人 ≥ 8、无 P0、最多 3 轮」是编排者临时加严的条件，本裁决按加严后的条件判。
- 修复清单里有 4 项（#2、#8、#9 和 P2 的 (c)）来自 TT 真机实测，不是审阅报告里的发现，由编排者直接加入。#2 按 P0 计。
- 冻结的庄园页问题不计分，但照样记录，留给 Blender 版庄园页。
