# E5 第 2 轮 · 手机首用玩家

人设：第一次用，iPhone 上的酒馆 App，单手操作，没看过说明。只想知道三件事：我在哪、附近出了什么事、庄园长什么样。

## 1. 环境

- 被测版本：`cloud/tc-mid-low` 分支，HEAD 3f9ba38。工作区里另有 `blender/tc_clouds.py` 和 `tc_upper.json` 的未提交改动，与 UI 无关。
- 服务：本地 `http://localhost:5178/`（`tools/cors_server.py`，不压缩）。
- 浏览器：
  - Playwright WebKit，iPhone 13 配置，375×812，DPR 3，触屏
  - Chromium，375×812，DPR 3，触屏，Android UA
- 节流：网络和 CPU 都不节流。
- Blender：每次运行前 `pgrep` 都没有查到 Blender 进程（`r.json` 里 `blender: false`）。Chromium 那一轮的计时明显偏慢（首屏 4.6 s），原因不明，所以计时只采用 WebKit 的数字。
- 测法：
  - 宿主模拟页 `map/tavern/test-host.html` 加悬浮按钮（卡内脚本 `eden-map.js`）
  - 当前地点用 `fireUpdate()` 模拟 MVU 变量更新
  - 事态用 `B.postEvents` 按 `eden-map:events` 协议 postMessage 发给地图
  - 另外单独打开 `viewer.html`（不嵌入），作为对照
- 脚本：scratchpad `e5/rev2/work/phone/`，共 4 个：
  - `run1.mjs`：嵌入的全流程
  - `run2.mjs`：独立页，EN 浅色和中文深色
  - `diag.mjs`、`diag2.mjs`：溢出诊断
- 截图目录：同目录下的 `iphone_zh_dark/`、`iphone_zh_dark_short/`、`phone_en_light_short/`、`standalone/`、`diag_*`。

## 2. 总分：**6.5 / 10**（有 1 个 P0，不过门控）

如果去掉 P-01，我会给 8。其余部分确实比 E4b 的 7.5 好：底部抽屉、层切换器、事态横条、庄园底部两排都理顺了。但在真实的 CDN 部署下，或者界面切成 EN 时，手机上的面板会被宿主标题栏撑宽。结果是关闭按钮、「⋯」菜单、卡片的关闭按钮都被推到屏幕外面，首次使用的玩家会被困在全屏面板里。

## 5. 一句话结论

手机端的查看器本身已经到 8 分左右的水平。但卡内脚本的标题栏在 grid 布局里没有 `min-width:0`：只要是 CDN 部署（带线路按钮）、界面是 EN，或者当前地点稍长，关闭按钮和「⋯」就被推出屏幕，玩家被困住。这是 P0，改一行 CSS 就能修，修完复测，我预计能到 8。
