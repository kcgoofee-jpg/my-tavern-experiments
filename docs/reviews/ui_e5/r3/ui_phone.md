# E5 第 3 轮 · 手机首用玩家

人设：第一次用，iPhone 上的酒馆 App，单手操作，没看过说明。只想知道三件事：我在哪、附近出了什么事、庄园长什么样。

## 1. 环境

- 被测版本：`cloud/tc-mid-low` @ dbc928b。工作区另有 `blender/*`、`tc_upper.json` 等未提交改动，与 UI 无关。
- 服务：本地 `http://localhost:5178/`（`tools/browser/lib.mjs` 的 `ensureServer`，不压缩）。
- 浏览器（每次只开一个，经 `lockrun.sh` 串行）：
  - Playwright WebKit，iPhone 13 配置，375×812，DPR 3，触屏
  - Chromium，375×812（P-01 复测另加 414×896），DPR 3，触屏，Android UA
- 节流：网络和 CPU 都不节流。
- **Blender 在后台渲染**：
  - 测试期间有 pid 17831 常驻。
  - 另有 pid 39250 在跑 `tiancheng_upper.py --res 10000 --samples 16` 的局部渲染，系统 load 从 5.6 升到 11.9。
  - Chromium 用软件 GL，受影响很大：打开到首帧 4.1–17.9 s，进庄园首帧 18–33 s。上轮同样的测法是 4.6 s。所以 Chromium 的计时不采用，只用 WebKit 的计时。
- 测法：
  - 宿主模拟页 `map/tavern/test-host.html` 加悬浮按钮（卡内脚本 `eden-map.js`）
  - 当前地点用 `fireUpdate()` 模拟 MVU 变量更新
  - 事态用 `B.postEvents` 按 postMessage 发给地图
  - 另外独立打开 `viewer.html`，作为「没有当前地点」的对照
- 脚本目录：scratchpad `e5/rev3/work/phone/`
  - `p0.mjs`：P-01 专项复测，结果在 `p0/p0.json` 和 `p0/*.png`
  - `run1.mjs`：嵌入全流程，分两组：`iphone_zh_dark/`，以及 Chromium EN 浅色 `phone_en_light_r/`
  - `run2.mjs`：独立页，结果在 `standalone/`
  - `timing.mjs`：只测打开时间，每种浏览器 2 次
  - 拼图：`sheet1.png`、`sheet2.png`、`sheet3.png`

## 2. 总分：**8.0 / 10**，无 P0，**过门控**

上轮的 P0 已修好。上轮说过「修完 P-01 我给 8」，这轮复测的结果与此一致。

- 在 4 组条件下，标题栏都不再把面板撑宽：
  - iPhone 375 × EN
  - iPhone 375 × 中文
  - Chromium 375 × EN
  - Chromium 414 × 中文
- 这 4 组都带线路按钮，当前地点用了 60 字的超长名字。
- 其他问题基本都是 P3 打磨项：设置抽屉缺分组标题、飞行落点下方有黑边、EN 下的中文残留。
