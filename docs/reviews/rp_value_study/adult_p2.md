# 人设 A2 · 享乐型成年玩家（32 岁，偏好多角色、多地点，追求新鲜感，频繁换场景和对象；桌面 SillyTavern 为主）

> 说明：本文只讨论功能、流程、隐私与沉浸感。卡内成人向 / 私密场景一律中性指代，不涉及具体内容。所有角色均为成年人。

## 1. 我什么时候、为什么在成人向 RP 中打开地图；看什么
- **挑下一个场景时**：我一个会话里会换 5–10 个地点。地图对我来说是**场景菜单**：庄园 F1–F5 有 58 个编号房间（`docs/eden-estate.md` 第 4 节，101 大厅、119 会客厅、202 茶室、218 晨读室、312 主人起居室、501 屋顶露台、502 眺望亭……），外面还有玫瑰园、绿篱迷园、人工湖、英式风景园、果园等十几个园林分区（2.3 节）。我打开地图不是为了确认「我在哪」，而是找「还有哪里没去过」。
- **换对象前**：想和另一个角色开新场景，要知道「她现在在哪、离我多远」。目前 `eden-map.js` 只推送 `getHere()` 读到的 `stat_data.世界.当前地点`，也就是只有我自己的位置，其他角色的位置地图完全不知道。
- **确认跟随没丢**：场景切得快，模型写「你们转到湖边」，我看标题栏 `em-here` 有没有跟着变。`here.mjs` 的逐级回落（房间 → 区域 → 庄园 → 地标）保证跟随不会卡住。
- **角标**：`recompute()` 扫最近 `SCAN = 40` 楼，出角标我会看一眼；对我来说事件是「附近有什么新的场景机会」，不是新闻。
- 一次打开 5–15 秒，频率高（每 10–20 楼一次）。看的是地点名和人，不是底图。

## 3. 什么会让我停用
- **地图只有一个人**：多角色玩法下只显示自己的位置，地图就只是一张好看的平面图，打开两次就没理由再开。
- **场景库看起来很小**：房间名藏在深层、要层层点进去才看到，或者园林分区没有名字，我会以为「就这几个地方」。
- **跟随慢半拍**：连续换三个地点，地图还停在第一个；或 `世界.当前地点` 写了园林里某处小景点，回落到「庄园」整体，等于没跟。
- **任何过滤或改写**：地点名、别名、角色名因词汇被改动。`docs/content-compat.md` 已明确不做关键词过滤，这条要长期保持。
- **操作成本高**：换一次场景要开地图 → 切层 → 进庄园 → 选楼层 → 找房间，比直接打字慢。

## 5. 架构上该怎么支撑我
- **角色位置走同一套定位**：`here.mjs` 的解析（含自定义叫法与逐级回落）抽成通用函数，对 MVU 里每个角色的位置字段各跑一次；外挂脚本推送 `{ self, others: [{ 名称, 地点 }] }`，查看器画头像点。字段路径做成配置（卡作者声明），不硬编码本卡。
- **扩展接口补两个订阅**：`EdenMap.on('here')` 之外加 `on('people')`，并提供 `EdenMap.getRooms()` 返回可列举的房间 / 分区目录，让用户脚本能做「随机场景」「清单视图」而不用改查看器。
- **地图 → 聊天只填不发**：点击房间 / 头像后由外挂脚本写入 ST 输入框，模板本机可改（`EdenMap.setActionTemplate`），不自动发送、不走网络。
- **本机状态按聊天隔离**：去过标记、标签、别名存 localStorage 时 key 带 `chatKey()`（事件已读已经这么做），避免跨存档串味。
- **不审核**：角色名、地点名、用户标签一律原样存取显示；认不出的地点照 `here.mjs` 规则回落，不丢弃。所有个性化只在本机，仓库只放中性目录与空示例。

## 6. 一句话结论
对我这类玩家，地图的价值在于「一眼看到还能去哪、谁在哪」：先做角色位置板和一键「去这里 / 找这个人」，再做去过标记与房间清单；渲染和 3D 维持现状即可。
