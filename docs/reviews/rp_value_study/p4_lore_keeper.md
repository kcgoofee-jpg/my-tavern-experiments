# P4 · 世界观 / 设定党

> 我拿地图当「可视化的世界书索引」，不是当壁纸。好不好看是其次，**对不对、能不能查到出处**是第一位。

## 1. 什么时候打开、看什么
- **模型提到一个我记不清的地名时**：打开地图点它，看地点卡的 `src`（`viewer.html` `showCard`）。我先看标签是「设定」还是「推断」（`tag: inf`，空心针），再看原文那一行。
- **判断模型有没有写错层级时**：比如模型让角色从下层走到银冠堡。我会看左侧上 / 中 / 下层切换器和面包屑，确认「世界 → 天城 → 三层 → 伊甸庄园」这条链，以及层间检查点和 7 号井是不是在同一平面位置（`maps.json` 里写着「同一平面位置」）。
- **事件标签落点后**：我要核对它落在哪个地标上，还是落在「位置不详」的虚线圈里（`map-events.md` 地点解析第 3、4 条）。落在虚线圈里就说明模型编了一个设定里没有的地名，这对我是很有用的信号。
- 真正看的顺序：地点卡的出处 > 层级关系 > 事件落点 > 画面。

## 3. 什么会让我弃用
- **画面和设定对不上**：比如上层 9 个地标里有 7 个是推断（`maps.json` `tc_upper`），但画出来一样逼真、一样确定。真实感越高，推断的内容越像「官方设定」，误导也越大。渲染越好看，这个风险越大。
- **文档、代码和实际行为不一致**：
  - `map-events.md` 写「扫描最近 200 楼」，`eden-map.js` 里是 `SCAN = 40`；
  - `map-events.md` 和 `event-taxonomy.md` 都还写着 `BLOCK` 整条丢弃，但 `content-compat.md` 写的是已去掉关键词过滤（6dd392e），`events.mjs` 里也已经没有 `BLOCK` 了。

  设定党最先翻的就是文档。
- **出处写成「推断」两个字就完事**：财团家族庄园、将军官邸的出处都只有这两个字，我没法判断推断依据是什么。
- **层级跳错**：当前地点落错层，或者世界图把天城内部地点归错。

## 5. 对「渲染还要做几轮」的意见
- 「与设定一致」的渲染还值得做：伊甸在全图最大、银冠堡的位置、检查点与 7 号井上下对齐、推断内容在视觉上弱化。这些每一条都比多一轮美观值钱。
- 「好看」这一项，A7 和 B2 做到现在已经过了我的阈值。再多一轮，只会让推断内容更像正史。
- **一句话**：渲染以「对得上设定」作为收尾门控，美观不再加轮次；省下来的时间用来补出处链接、修正文档与代码不一致、在底图和地点卡上区分推断。
