# 用户内容兼容（技术兼容，不审核）

用户 2026-09-27：「用户说在自己的庄园里面想干嘛干嘛，我们做的是技术兼容，that's it。」「屏蔽词命中不要做。」

原则：
- 地图**不审核、不过滤**用户聊天里的内容：事件标签原样解析、原样落点；当前地点原样解析。发生了什么，地图不需要知道。
- 仓库和公开 CDN 只放中性的地图、建筑、设定数据；用户自己想加的东西，走**本机**扩展，只存在用户本机。

## 现状
| 环节 | 行为 | 位置 |
|---|---|---|
| 事件标签 | 不做关键词过滤；认不出的类型归「其他」（灰色方块） | `map/tavern/events.mjs` |
| 当前地点 | 逐级回落：房间 → 区域 / 楼层 → 庄园 → 地标 → 层 → 天城 → 世界；都认不出就不动地图 | `map/here.mjs` |
| 自定义房间叫法 | 本机表 `{ rooms: { 自定义名: 标准房间名 } }`，当前地点写自定义名时落到对应房间 | `here.mjs` 的 `buildIndex(…, custom)` |

## 本机扩展接口（预留，数据只在用户本机）
查看器暴露 `window.EdenMap`（嵌在酒馆里时，外挂脚本转发同名调用）：
- `EdenMap.setRoomAlias(自定义名, 标准房间名)` / `EdenMap.removeRoomAlias(自定义名)` / `EdenMap.getRooms()`：自定义房间叫法，存本机 `localStorage` 的 `edenMapCustom`。
- `EdenMap.renameRoom(标准房间名, 显示名)`：地点卡和标签显示用户自己的名字（只改显示，不改落点）。
- `EdenMap.registerOverlay({ id, map, draw(ctx) })`：在某张地图上加用户自己的图层（SVG / Canvas），由查看器负责坐标换算与开关；`unregisterOverlay(id)`。
- `EdenMap.on('here' | 'events' | 'map', fn)`：订阅当前地点、事件、切图，给用户自己的脚本用。
- 这些接口不联网、不上传；仓库里只有接口和空的示例。
