会话记录关键词出现次数（**实测**，含工具输出，只能看出趋势）：重渲 119、re-render 69、遮挡 40、条纹 33、模糊 30、楼梯 28、黑块 26、裁 18、拉伸 9。Blender 崩溃有 Metal 编译 kernel 缓存时 `NSURL fileURLWithPath` 抛异常的记录（路径含中文“性能/”）。

**主要浪费**：(1) 同一张 8K 反复整张重渲，而不是局部补丁；(2) 依赖顺序反了，底图先定稿，建筑 / 伊甸后改，只好再渲；(3) 给非卡内容建模或加细节，事后删掉；(4) 评审默认 2–3 轮，但第 2、3 轮平均只涨 0–0.5 分。

## 2. 质量改进（按类型）

- **① 底图**：固定曝光 / 太阳预设（`tc_common.py` 里的 `PRESET_DAY/NIGHT`）；出 8K 前一定要跑 `--crop` 检查三块：最亮处、最暗处、最密处；发光面只自发光，不参与间接光。
- **② 庄园**：烘焙后自动查纯黑顶点色 / 纯黑贴图（直接判失败）；手机清晰度目标：375 px 宽下 DPR 2 能认出门窗；三维浮层默认收起，底部面板高度 ≤40%。
- **③ 地标**：动手前先过参考清单（真实参照 2–3 张、卡原文行号、名字照抄卡）；相机预设 `frame_all(margin=0.08)` 保证不裁顶；`common.py` 做材料库（石、玻璃、钢、混凝土、瓦楞铁，按世界尺度统一 UV，避免拉伸）；glb 预算：标准档 3 MB，低档 1.5 MB。
- **④ 参考 / 草稿**：用户否过的设计列进 `docs/rejected.md`，每次出草稿前先对一遍。
- **⑤ 补丁**：`region_patch.py` 补一次接缝检查（补丁边缘两侧的色差阈值）。

## 3. 流程优化

1. **卡内范围门控**：建模前先写“卡原文行号 + 原名”；找不到出处的不建，只能问用户（遵守 card-canon-names、modelling-scope 两条记忆）。
2. **默认只评审一轮**：评审出 P0 或分数低于 7 才开第二轮。
3. **先出草稿**：Eevee 或 Cycles 16 spp、2000 px 定构图，之后才出 Cycles 定稿。
4. **GPU 排队**：一次只跑一个 Blender；多个渲染任务写进队列，一起跑（夜间批）。
5. **局部补丁优先**：改动面积 <25% 时必须走 `region_patch.py`，整张重渲要写明理由。
6. **依赖顺序**：几何定稿在前，时段变体（晨 / 昏 / 夜）在后；上层建筑（含伊甸）定稿在前，上层 8K 合成在后。
7. **崩溃处理**：设 `TMPDIR=/tmp/blender_tmp`（纯 ASCII 路径），缓存目录也放在 ASCII 路径下；崩溃后自动重试一次。
8. **资产缓存**：CC0 贴图 / HDRI 经 `fetch_assets.py` 放进共享缓存；场景构建结果存成 `.blend`，改材质时不用重建几何。
9. **云 GPU（可选）**：全量 8K 批（4 层约 1.7 小时，**实测**）可以放到 RunPod / Vast 上的 RTX 4090（估 0.4–0.7 美元/小时，估计比 M 系列快 2–4 倍，一批不到 1 美元）；前提是脚本不依赖 Metal，路径全用 ASCII。
10. **推送规范**：一律 fetch → rebase → `tools/bump_head.py --push`；不要 reset 到过期的 origin（10f6c2c 回退掉圣铁摇篮的提交就是这么来的）。
11. **少用额度**：同时最多 2–3 个 agent；评审人设从 4–5 个减到 2 个（建筑 + 卡）。用户记忆要求只用 Opus，这条保持；如果用户以后放宽，再把模板化的地标批量、文档同步、补丁这类活交给 Sonnet。
