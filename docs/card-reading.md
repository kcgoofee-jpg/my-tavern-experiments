# 完整读卡流程（可复用）

目的：给地图 / 外挂脚本做兼容前，把一张角色卡及其世界书**逐字读全**，得到可核对的事实底表，并和仓库逐条对账。2026-09-27 在「Yehehua 的原作卡」上跑通：一次通读 + 四路分角度 + 一路补读，共找出 20 + 24 + 12 + 14 条遗漏 / 错误。

## 0. 原则
- **只读**：先把卡复制到 scratchpad 再解析，永远不写用户的酒馆数据目录。
- **一个人读不全**：单读者会按需跳读，必然漏。至少「一次通读 + 多角度复读 + 补读」。
- **证明读全**：每个读者必须写出「读过的文件 + 行号范围」；最后求并集，对照每个文件总行数，剩下的要么补读，要么写明原因（纯代码、与已读文本逐条相同）。
- **只摘和用途相关的事实**：公开仓库里一律中性表述，不转述露骨内容；纯露骨段落记为「已读，无地图相关事实」。
- **对账而不是摘要**：每个读者都要输出 MISSED（仓库没有的事实）和 WRONG（仓库与卡矛盾之处，附行号），修正由单独的执行者统一改，避免多人并发改同一批文件。

## 1. 导出
1. 从 PNG 的 `tEXt` 块取 `ccv3`（优先）和 `chara`，base64 解码成 JSON。
2. 落地为文件：`ccv3.json`、`chara.json`、`book.txt`（卡内世界书全部条目，含禁用）、`greet.txt`（first_mes + 全部 alternate_greetings）、`ext.txt`（regex_scripts、tavern_helper 脚本、depth_prompt 等全部扩展字段）、`world*.txt`（`extensions.world` 指向的外部世界书及其他关联世界书）、我们自己的附加世界书。
3. 记下每个文件的总行数，作为覆盖核对的分母。

## 2. 通读（1 人）
逐字读完全部文件，写一份中性的事实摘要（本仓库是 `docs/card-digest.md`）：世界结构与地名、交通、时间系统、势力、人物身份与住处、专属场所（如庄园房间）、每个开局的时间与地点、变量结构、正则与脚本各做什么；最后列「仓库与卡不符」清单。

## 3. 分角度复读（4 人并行，互不看对方）
| 角度 | 重点 |
|---|---|
| 地理与地点 | 每个具名地点、所在层 / 区、相对位置、尺寸高度；层与层的关系 |
| 人物、势力与关系 | 身份、归属、住处 / 常在地、亲属与关系网、名字写法变体、立绘地址 |
| 系统、界面、正则与脚本 | 变量结构的真实键名与枚举、更新规则与注入深度、状态栏与开局菜单的实现、存储键、全局名、z-index、事件钩子；与我们脚本的冲突与可利用点 |
| 剧情、开局、时间与事件 | 每个开局的时间 / 地点 / 移动 / 在场者、作息顺序、隐含的事件与节日、出行模式 |

每人输出：事实表、MISSED、WRONG、覆盖证明（文件 + 行号）。

## 4. 补读（1 人）
汇总四人的覆盖范围求并集，逐字补读没人读过的段落；用脚本核对重复文本（外部世界书 vs 卡内世界书、ccv3 vs chara）以免重复劳动；输出覆盖表，证明每个文件每一行都有人读过。

## 5. 汇总与执行
- 把全部 MISSED / WRONG 去重合并成一张清单，按所属文件分给**互不重叠**的执行者（本仓库：运行时与界面一人；数据、文档、事件分类一人）。
- 执行者改完跑全部自检和测试，按主题分批提交，更新变更记录。
- 读卡事实写回摘要文档，作为之后所有工作的依据；以后再有人说「卡里有 / 没有 X」，先查摘要。

## 6. 常见坑（本次踩过）
- 把模型在聊天里写出的词（如「私人飞行器」）当成设定；以及反过来，漏掉卡里只出现一两次的设定（「专线空运」）。
- 同一个词在卡里另有含义（本卡的「跃迁」指阶层上升，不是瞬移）。
- 开局页、状态栏这类正则 HTML 里藏着作者署名、链接、立绘地址，只读世界书会漏掉。
- 变量结构是严格的（zod），外部加的字段会被删掉；读真实键名，不要用摘要里的意译名。
- 人名有长短写法、编号后缀、与亲属撞名，匹配前要规范化。
- 读者会谎报「已读完」，必须要行号范围。
