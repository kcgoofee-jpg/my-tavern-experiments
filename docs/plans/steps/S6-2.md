## 0. Why

Plan §5 Stage C, S6 and decision D4: items are stored in one place, `<chat var>.stash` (`eden_map.stash` for the first
pack); the v1 keys `仓库` (inventory) and `槽位` (W12 virtual slot) migrate automatically; a recompute from the chat log must
match the store item for item (agent brief §2.4, kernel K-R47). Today two keys hold Chinese-keyed shapes
(`tavern/stash-store.mjs`, `core/ledger.mjs` slot functions) and the host flow `tavern/loot-flow.mjs` writes them through
the W11 audit. After this step one ASCII store holds both, the flow is `tavern/stash-flow.mjs`, a pure fold rebuilds the
store from the messages, and the **injected text is byte-identical** for the same rows. The Items tab is S6-3.

- `SRC = ['text', 'map', 'api', 'legacy']`, `TEXT_NOTE = n => '正文拾取 · 第 ' + n + ' 楼'` (verbatim today's note).
- `empty(msgIndex)` → `{ v: 1, items: {}, seq: 0, slot: null, removed: {}, since: msgIndex ?? null, upTo: msgIndex == null ?
  null : msgIndex - 1 }`.
- `norm(raw)` → a valid store (design §5.2): drops rows without a name; cuts `name` 60, `place` 60, `map` 40, `note` 200;
  `node` kept only when it matches `^[a-z_][a-z0-9_]{0,63}$`; `qty` 2–999 else absent; `src` outside `SRC` → `'legacy'`;
  `carried` boolean (default: `src` is `text` or `map`); `msgIndex` integer or null; `mark` string ≤ 16 or absent;
  `removed` ≤ 200 entries (oldest by value dropped); `seq` as v1 (`max(seq, numeric part of 'i<n>' ids)`); `slot` through
  `ledger.slotNorm` (T3) or null.
- `migrate(root, { msgIndex, worldIds })` → `{ stash, migrated }`: when `root.stash` is a plain object → `{ stash:
  norm(root.stash), migrated: false }`; else when `root[V1_KEYS.inventory]` or `root[V1_KEYS.slot]` is a plain object →
  rows mapped per the design §5.4 table (v1 `norm` first: same cuts, same `seq`), the id rule for `src` / `carried`
  (`itemId(name) === id` → text; `worldIds.has(id)` or `/^s[0-9a-z]{1,8}$/` → map; else legacy), the slot mapped per §5.4,
  `since = msgIndex`, `upTo = msgIndex - 1`, `from = { keys: [present v1 keys], msgIndex }`, `migrated: true`; else
  `{ stash: empty(msgIndex), migrated: false }`. Never mutates `root`.
- `put(stash, { id?, name, place?, map?, node?, note?, hidden?, qty?, src = 'api', carried?, msgIndex?, mark? })` →
  `{ stash, changed }`: same id rules as v1 `put` (given id; else by name; else `'i' + (seq + 1)`), same "empty field keeps
  the old value" rules for `place`, `map`, `hidden`, `note`, `qty`; `carried` default from `src`.
- `remove(stash, idOrName, msgIndex)` → `{ stash, changed }`; a removed `text` row leaves `removed[id] = msgIndex`.
- `retag(stash, worldIds)` → `{ stash, changed }`: rows with `src: 'legacy'`, `msgIndex: null`, in a store that has `from`,
  whose id is in `worldIds`, become `src: 'map'`, `carried: true` (the world stash may load after the migration ran);
  idempotent.
- `findRow`, `rows(stash, q)` — v1 semantics on the new fields (`q.place`, `q.map`, `q.name`, `q.hidden`, plus

- `recompute(msgs, { since, actions, removed, worldNames, vocab, probe })`: `empty(since)`; apply actions whose `msgIndex`

  actions, ordered by `msgIndex` (null first) then by insertion order.
