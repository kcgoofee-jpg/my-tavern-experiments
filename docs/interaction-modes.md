# 脚本 ↔ 卡 交互方式评估（(a)(d)(e) 已实施，见文末「实施记录」）

目标：长聊天里模型注意力衰减导致变量 / 标签漂移或漏写；以及被杀、卡死、断网、swipe/重生/编辑/分支时仍然正确并能恢复。内容中立：所有方案只处理「状态字段」，不看、不过滤正文内容。源码依据见 `docs/mvu-integration.md`。

## (a) 紧凑状态注入（setExtensionPrompt / injectPrompts 固定深度）

- **做法**：每次生成前（`GENERATION_AFTER_COMMANDS`）把「当前地点、在场人物、世界时间、进行中的行程」拼成一段 ≤150 token 的状态块，按固定 id、`in_chat` 深度 2–4 注入（TH `inject.ts:21-55`；ST `script.js:8926`）。数据来自 `pickStat` 选出的快照，pending/stale 时注明「上一楼状态」。
- **收益**：模型不必从很深的历史里回忆地点，这正对准注意力衰减；地图已经在同一钩子注入「事态」（`eden-map.js inject`，深度 4），基础设施现成，边际成本很低。
- **代价**：每轮多约 100–150 token；需要和卡自带的 MVU 状态提示去重（很多 MVU 卡已经把 stat_data 放进提示词）。
- **风险**：注入错数据会被模型当真 → 只在 ok 时注入完整值，stale 时加「未确认」标注；与卡的 `[mvu_update]` 规则冲突的措辞要中立（只陈述状态，不下指令）。
- **TT / iPhone**：纯前端，无网络，全平台一致。
- **用户需配置**：设置里一个开关 + token 上限（默认开，150）。
- **建议**：**首选，下一步就做**。先做检测：卡的提示词已含 stat_data 时自动只注入卡里没有的字段（行程、事态）。

## (b) 副 API「状态守门员」

- **做法**：每次回复后用便宜模型读最后一楼正文 + 当前快照，输出校正后的状态（或只做校验，发现缺失时提示）。
- **收益**：能补「模型忘了写命令」这一类漏写。
- **代价**：每楼一次额外请求（小模型约 1–3k 输入 token），延迟 2–10 s；需要用户自己的 API key。MVU 已经内置同类能力——「额外模型解析」模式（MVU `on_message_received.ts:45-139`，设置 `更新方式`，`store.ts:230`），地图再做一套会重复且会和 MVU 抢写。
- **风险**：两个写者竞态；key 存储与费用；断网时整条链路失败；iPhone 后台时请求被挂起。
- **TT / iPhone**：TT 可发请求，但 iPhone 后台必断，需要回前台重试。
- **用户需配置**：API key、模型、预算上限。
- **建议**：**不做**。在自检里提示「长聊天可在 MVU 设置里开『额外模型解析』」，把这件事交给 MVU。

## (c) 数据库插件式结构化存储（shujuku）

- **做法**：状态存成表（地点表、人物表），由插件的额外生成请求填表，自己的世界书条目注入（`docs/content-compat.md` §表格数据库插件）。
- **收益**：结构清楚，可查询；插件已有用户群。
- **代价**：填表本质上也是副 API（同 (b) 的成本）；表结构由插件与卡决定，地图写入需要共同约定。
- **风险**：双写者；插件接口变化；和 MVU 并存时两份真相。
- **TT / iPhone**：插件本身在 TT 可用性取决于其版本；地图只读不受影响。
- **用户需配置**：安装插件、配表。
- **建议**：**维持只读兼容**（MVU 缺地点时读主角表，表更新回调触发重读）。只有原插件作者主动提议共同字段时再谈写入。

## (d) 显式标签确定性解析 + MVU 为准，地图对账

- **做法**：地图已经解析正文里的人物位置 / 事态标签（`events.mjs`、`characters.mjs`）。对账规则：MVU 快照 ok → 以 MVU 为准；本楼 MVU 缺失（pending/stale）但正文有明确地点标签 → 用标签值，标「来自正文」；两者冲突 → 显示 MVU 值并在自检里列出冲突楼层。
- **收益**：零额外请求；把「模型写了正文但漏了命令」的一部分情况救回来；完全确定性，可测。
- **代价**：需要卡或世界书附加条目约定一个标签格式（附加条目本来就是我们的交付物）。
- **风险**：标签本身也会随注意力衰减漏写——所以只作补充，不取代 MVU。
- **TT / iPhone**：纯前端。
- **用户需配置**：无（世界书附加条目自带说明）。
- **建议**：**第二优先**，与 (a) 配合：(a) 降低漏写率，(d) 兜底。

## (e) 聊天变量里的检查点 / 日志

- **做法**：在 `eden_map` 里存 `{chat_len, floor, swipe_id, hash(stat 关键字段)}` 检查点；重开时比对：楼层 / swipe 对不上就说明中途被杀，重新推导并提示。
- **收益**：能识别「防抖保存前被杀」（TH `variables.ts:148/153` 都是防抖保存）。
- **代价**：每次都写聊天变量会触发保存——必须只在值变化时写（v0.9.9 已加幂等写）。
- **风险**：聊天变量本身也是防抖保存，检查点可能和它要检查的东西一起丢；所以只能「发现不一致」，不能「恢复数据」。真正的恢复源是 chat 数组 + MVU 的 `restoreVariables` 重演。
- **TT / iPhone**：纯前端。
- **用户需配置**：无。
- **建议**：**小范围做**：只记最后确认的楼层号与 swipe，用于决定 stale 提示；不要做完整日志。v0.9.9 的 `pickStat` 已覆盖大部分需求（数据从 chat 数组推导，不依赖检查点）。

## (f) 生态里的其他做法

- **MVU 自己的「额外模型解析」+ 自动恢复变量**：已经是 (b)+(e) 的官方实现，优先引导用户用它。
- **世界书「常驻 + 深度」条目携带状态宏**：卡作者可在世界书里写 `{{get_message_variable::stat_data.世界.当前地点}}` 一类宏由 TH 渲染，效果同 (a)，但需要改卡——我们不改卡，所以由地图注入代替。
- **iframe 消息楼状态栏**：只是显示，不解决注意力问题。

## 结论

1. **(a) 紧凑注入**：先做，收益最大、成本最低、全平台一致。
2. **(d) 标签对账**：随后，作为 MVU 缺失时的确定性兜底。
3. (e) 只保留「最后确认楼层」这一最小检查点；(b)(c) 不自建，交给 MVU / 数据库插件，地图保持只读。

## 实施记录（2026-09-28，(a) + (d) + (e)）

纯逻辑在 `map/tavern/modes.mjs`（node 单测 `tests/modes.test.mjs`），接线在 `map/tavern/eden-map.js`「交互方式 (a)(d)(e)」一节；浏览器验收 `tools/browser/th_adopt.mjs`。

### (a) 紧凑状态注入
- 一行：`[地图状态] 地点：…；在场：…；时间：…；行程：…`。粗估 token 超过上限时，先砍行程，再砍在场名单，地点始终保留。
- 固定 id `eden-map-state`，`in_chat`、`role: system`、`should_scan: false`；每次先 `uninjectPrompts` 再 `injectPrompts`，重生 / swipe / 重载都只有一条。TH 在 pagehide 时会撤掉全部注入，新实例启动时重新注入一次。
- 选哪一楼的状态：普通发送用 `pickStat(最后一楼)`；`GENERATION_AFTER_COMMANDS` 的 type 是 `swipe` / `regenerate` 且最后一楼是助手楼时，从它的前一楼开始找，因为被替换那一楼的变量是旧回复写的。
- 快照是 pending / stale 时，来自快照的字段标「（未确认）」。
- 去重：读 `getCharData('current')` 的描述、场景、系统提示、历史后指令、示例、开场白和卡内世界书。文本里引用了 `stat_data.<路径>`、`get_message_variable` / `getvar` 读了该字段，或者整个 `stat_data` 进了提示词时，跳过那个字段。行程永远注入。
- 设置：「数据与映射 → 状态注入」开关（默认开，`edenMapStateInj`）；「高级 → 状态注入」深度（默认 2，`edenMapStateDepth`）与 token 上限（默认 150，`edenMapStateBudget`）。三项都走脚本变量偏好。
- 原有的「事态」注入（`eden-map-events`，深度 4）不变，两条并存。

### (d) 标签对账
- MVU 为准。最新一楼 MVU 没有快照（pending / stale / 读不到地点），而这一楼正文里有明确的玩家地点标签时，改用标签值。标签可以写成 `⌖地点 层·地点`（隐藏 span 或裸写），也可以写成 `data-tcmap="地点=…"`（不带 人物 / 类型 / 标题）。这时 `hereSrc = 'tag'`，`eden-map:moved` 的 source 也是 `tag`。
- 世界书附加条目「地图当前地点」加了一行【地点标签】说明，模板原文不生效。
- 自检新增一项 `conflict`（info）：最近 30 楼里 MVU 地点和标签不一致的楼层，最多 10 条，只列出、不改。

### (e) 最小检查点
- `eden_map.检查点 = { 楼, swipe }`：只有快照 ok、而且就在最新楼时才前进。内容没变不写，跟着 `saveRoot` 走，本来就是幂等写。
- 启动（`loadCustom`）时对照：
  - `match`：不处理。
  - `ahead`：之后有助手楼没有快照，按「未确认」显示并重推。
  - `swiped` / `missing`：检查点作废，从聊天记录重推，下次确认时重写。
- 除 `match` / `none` 外，自检多一项 `checkpoint`（info）。检查点只用来发现不一致，数据仍然从聊天数组和楼层变量推导。
