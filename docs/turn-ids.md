# 本轮闭合词表与标签校验（TURN-IDS）

> 状态：已实现，开关 `edenMapTurnIds` 默认关。开关关 = 与今天的行为完全一致（零差异）；开关开 = 注入词表 + 启用校验与诊断环。
> 来由：WB-1 实测模型在约 6% 的回复里写地图标签。外部项目 ilw-native-owner（无许可证，只取思路不抄代码）用四件事把状态更新做到可靠。本文逐条对到我们的行标签体系上，说明收哪条、怎么收、代价在哪。
> 代码：纯逻辑 `map/tavern/turn-ids.mjs`（词表行 / 注入通道 / 校验三入口 / 诊断环）；接线在 `eden-map.js`（校验）、`llm-flow.mjs`（每轮注入）、`interaction-modes.mjs`（地点标签守卫）、`context.mjs`（生成闸门）；规范条目改动在 `tools/build_worldbook_addon.py`（【词表】一句）。单测 `tests/turn_ids.test.mjs`。

## 1. 四条技术，收哪几条

| ilw 的做法 | 收不收 | 对到我们的体系 |
| --- | --- | --- |
| (1) 每轮注入本轮可用的 ID 闭合清单（当前层优先、邻近地点、被跟踪人物，附「不要自造 ID」） | 收 | 每轮注入一行「[本轮标签词表] 地点：…；人物：…」。清单从节点树按当前地点现算，写法与标签里要抄的字符串一字同源。规范条目加一句【词表】：出现词表时地点、人物名只能照抄表里的写法。 |
| (2) 回复末尾一个机器块，承载带类型的意图（JSON） | 不收 | 我们的隐藏 span 行标签就是「回复末尾的机器块」，只是形状是行不是 JSON。换成 JSON 块要同时改规范条目、解析器、OOC 模板、示范表，收益没有实测支撑（本备忘录没有），按 OUT 清单不做的决定执行。以后若 A/B 测出 JSON 块确实在标签出现率或准确率上更好，再立条目重开。 |
| (3) 分层校验（schema → 允许 ID → 非法转移 → 与地点映射一致），命名错误码进诊断环，被拒的块什么都不改 | 收（裁剪） | schema 层我们本来就有：解析器只收合规写法，收不进的一向当正文。允许 ID 层是这次新增的校验：地点、人物地点、事件落点要能在节点树里认出来。错误码三个：`place-unknown`、`char-unresolved`、`event-unplaced`。诊断环 = 「数据与映射」里新增的一节，最多 16 条、新的在前、同一条重写只更新时间不重复占位、换聊天清空。被拦下的标签 = 什么都不写（不上图、不更新位置、当前地点走原有兜底链，等于没写）。 |
| (4) 生成开始 / 结束与 swipe 跟踪，半截回复永不写状态 | 收（已有大半） | swipe：酒馆的 `mes` 恒等于选中 swipe、变量按 `variables[swipe_id]` 取，我们的读取路径整条建立在这个选择模型上（`tests/turn_ids.test.mjs` 在适配层边界钉住）。生成中：`readMsgs` 加第三参 `generating`——正在生成时窗口顶上那条助手楼整楼不进，半截标签永不解析；`GENERATION_ENDED / STOPPED` 本来就会触发重算，写完的楼照常进来。不需要单独的检查点机制：聊天记录是唯一真相，每轮从 80 楼原文重算，swipe / 删楼 / 编辑后自然一致。 |

「非法转移」一层没有收：它防的是「状态账本被写入不该发生的状态」，我们没有账本——状态每轮从聊天记录重推，不存在可被污染的中间态。

## 2. 词表行长什么样

```
[本轮标签词表] 地点：天城·中层·霓虹街、天城·中层·商业区、…；人物：雷恩、绫濑遥、…。标签里的地点与人物名只能照抄上面的写法；列表以外的宁可不写，不要自造。
```

- 地点名单与 JIT 激活集同源（`spatial-contract.mjs activationSet`）：当前地点排最前，其次是出口、同室房间、邻近地标。当前地点永不砍。
- 人物名单 = 最近 20 楼内有位置记录的跟踪人物（与注入状态行同一口径），上限 12 人。
- 预算 400 token 上限：超了先砍人物尾部，再砍地点尾部；砍到只剩提示句还超就不注入（宁缺勿滥，绝不为塞名单丢掉「只能照抄」这句约束）。
- 只教写法，不改任何标签语义：认得出但不在表里的写法照样能解析（校验层管拦，词表层只教）。

## 3. 缓存代价

词表每轮都变（人一动名单就换），所以它绝不能进缓存前缀。做法与状态行 / 空间契约一致：固定 id（`eden-map-turn-ids`）、`in_chat`、深度 0、`should_scan: false` 的系统注入，排在整段历史之后。每轮的差别只在末尾这一小节，前缀逐字节不动，酒馆 / 网关的 prompt 缓存在「注入词表」这个位置不受影响。成本就是每轮实打实的几百字符（上限 400 token，典型 60–150 token）；内容没变不重写（水位去重），开关关掉当场撤净（prefs 改动即时清 + 下一轮重算兜底）。

规范条目（`map.link-rules`）只加了【词表】一句约 60 字，常驻条目从 999 字符涨到 1058 字符。它在深度 0 末尾、卡的回复末尾规则之后（WB-2 / D45 版面），这一条本身是静态的，在缓存前缀里也只多这一句的开销。

## 4. 与 JIT 的关系

词表的地点名单与 JIT 的激活集是同一个 `activationSet` 计算的两种用法：JIT 拿它去开关世界书条目（跨轮生效、改变缓存前缀——书的增删会抖掉前缀缓存，靠低频写入与水位摊薄），词表拿它每轮注入（只在末尾、零缓存代价、只教写法不供细节）。设计上二者可以合流：如果 A/B 测出词表本身已能把「写到表内」维持在足够高的比例，可以考虑用词表替代 JIT 对「邻近地标条目」的开关（少一次书写入 = 少一次缓存抖动）。这一步需要测量数据，不预设结论；现阶段两个开关互相独立、默认都关。

## 5. 校验的边界（开关开着时）

- **只拦认得出的错**：节点树（事件落点用的那张 geo）没装好、resolve 本身抛异常时一律放行。校验器坏不拦好。
- **只管模型写的标签**：人物位置只校验 `src = 'tag'` 的记录；玩家的 OOC 纠正（D32）优先级更高、不校验；MVU / 同处推断 / 日程来源不校验。
- **事件**：开关开着时，落不了点（连层都对不上）的事件不再「未上图列出」，而是拦下记进诊断环。这是对 2026-09-27「不做内容过滤」契约的一次点名豁免：开 = 用户点名要拦，关 = 原样列出。两种行为都有测试钉住。
- **地点**：被拦下的 `⌖地点` 等于没写——当前地点回到 MVU / 数据库 / 预设兜底链，不会出现「哪都不在」。
- 诊断环只存最近 16 条、每条 ≤60 字，随 `eden-map:th-state` 一并不定时发给设置页；不落任何存储，换聊天即清。

## 6. 开关登记

`edenMapTurnIds`（localStorage，默认 `'0'`，pref:true，owner host）→ 协议 `eden-map:th-state.turnIds`（`object?`）→ 宿主 `thPrefs.turnIds` / `prefs` 写回 → 功能卡 C11（`fc.turnIds.*`，含注入行文本与 token 数）→ 「数据与映射」诊断节（`ti.*` 词条，zh + en）→ 档案页 HOST_PREFS。关 = 词表不注入、三个校验入口原样放行、诊断环不记。

**准备**

**A 组（开关关，基线）**：`本轮词表与校验` 关着，连打 50 楼。逐楼记三个数（看聊天渲染源码或地图自检即可）：

**B 组（开关开）**：换一个新聊天、同卡同档同开局，打开开关，再打 50 楼，记 A 组同样的三个数，另加：
- 设置 › 数据与映射 「本轮词表与校验」一节里被拦条数与原因分布（这一节最多留 16 条，超出的当场截图）。

**判读**
- B 组标签出现率明显高于 A 组、且「未上图」不升 → 词表有效，考虑把默认打开进下一版讨论。
- 拦下次数多但出现率没升 → 模型没在照抄词表，看被拦样本是不是词表里根本没有的地方（说明激活集漏了它，是名单问题不是服从问题）。
- 地点不符次数 B 组更高 → 立刻回报，可能是校验拦错了方向。

**回归**：跑完把开关关掉再打 5 楼，确认注入行消失（AI 联动页 C11 显示已关闭、聊天末尾没有词表消息）。
