# 自定义 v2 设计规格（名称与用途）

状态：设计稿（多数未实现，见 §C1–C12）· 基线 v0.9.6（`map/custom.mjs`、`map/tavern/picker.mjs`、`map/tavern/mvu.mjs`）· 2026-09-27（路径与版本 2026-09-29 校订：`custom.js` 已模块化为 `custom.mjs`）
示意：`docs/design/custom-v2/mock.html`（`?s=card|v3d|conflict|hub&theme=dark|light&lang=en`），PNG 在 `docs/design/custom-v2/shots/`（`node docs/design/custom-v2/render.mjs` 重出）。

## 0 结论

v0.9.5 功能已经齐了，但**入口放错了地方**：自定义只能从「设置 → 名称与用途」进入，再到选择器里找对象。用户其实是在看一张卡（地点、房间、人物、三维部件）的时候才想改名。v2 做四件事：

1. 每张卡加「✎ 自定义」，直接打开就地编辑抽屉。
2. 编辑时写明「模型会看到」的原文。
3. 剧情标签不再静默覆盖手动设置，改为待确认，并记历史、可撤销。
4. 三维部件纳入同一套数据，id 稳定，例如 `dairy:tank`。

设置页保留，改成管理中心。

## 2 概念模型（界面里统一这样说）

- **标准名**：卡里设定的名字，永远不变，剧情和存档都认它。界面上用小字灰色，写作「标准名：书房」。
- **你的叫法**（显示名，数据字段 `名`）：在地图、卡片、流程标签上替换标准名显示。
- **用途**（`用途`）：一句话，模型会当作背景。
- **旧叫法**（`别名`）：自动保存，不单独编辑，只出现在历史里。
- **来源**：`手动` 或 `剧情标签`，用徽章显示。剧情标签在待确认状态时用 accent 描边的「剧情标签待确认」。

这些文案只用这几个词。不再使用「显示名」「别名」「自定义项」。

## 3 就地编辑：每张卡的「✎ 自定义」

适用于四种卡：地图地点卡、庄园房间卡、人物卡、三维热点卡。

- **按钮**：放在卡片操作行的第一个位置。用虚线描边加 `--accent` 文字，表示这是次要但可发现的动作。最小尺寸 `--hit`（44 px）。已有自定义时文案改为「✎ 改」。
- **编辑抽屉**：示意见 `shots/card_*`。
  - 桌面：在卡旁弹出，宽 380 px。
  - ≤ 640 px：底部抽屉，操作条贴底，打开时不自动聚焦（沿用 r1 的修复）。
  - 抽屉内容从上到下：
    - 标题「自定义 · 〈标准名〉」；
    - 一句说明「标准名不变，剧情和存档都认它；这里只加你的叫法。」；
    - 「你的叫法」输入框（40 字计数）；
    - 「用途（一句话）」输入框（200 字计数）；
    - **「模型会看到」预览**；
    - 贴底操作条只有 取消 / 保存；「清除」降为内容区里的红色文字链（`--alert`，可撤销），避免拇指误触。
- **「模型会看到」预览**：
  - 实时显示这一项在 `summarizeCustom` 里的原文片段，也就是 `书房→星图室（夜里看星图，整理旧地图）`，用户改动的部分用 `--accent` 高亮。
  - 标题写「模型会看到（下一条消息起）」。
  - 如果整体摘要会超出 220 字、这一项会被截断，预览下方用 `--alert` 小字写：「摘要已满，这一项可能被截掉；开世界书同步可完整发送」。
  - 世界书同步开着时，再加一行灰字：「世界书条目：- 书房：玩家称为「星图室」；用途：…」（即 `wbContent` 的这一行）。
- **保存后的反馈**：
  1. 抽屉关闭，卡片标题更新，地图标签闪一次（`--dur-3` 描边脉冲）。开启减少动态时不闪，只更新文字。
  2. 出现 toast「已保存 · 撤销」，停留 10 s。
  3. 在读屏的 live 区域朗读同样的内容。

## 4 三维热点集成契约（给三维查看器实现者）

1. **稳定 id**：自定义里的键写作 `<prop>:<hotspot.id>`，例如 `dairy:tank`、`dairy:vacuum`、`dairy:receiver`。
   - **数据存在单独的 `eden_map.自定义.部件[<prop>][<hotspot.id>]`，不放进 `items`**。评审 P0：旧版 `summarizeCustom` 会把 `items` 里的 `dairy:tank` 原样拼给模型；分开存以后旧版读不到也拼不出来，回退只丢三维自定义。条目结构与 items 相同，`类` 固定 `part`。
   - 标准名取 `manifest.hotspots[].name.zh`，由选择器和提示词显示。
   - 数据键仍然用 id，因为中文名以后可能改。
   - 同名的 manifest 热点 id 发布后**不得改名**。要改就在 manifest 里加 `"was": ["旧id"]`，由迁移函数把旧键改成新键。
1b. **partIndex**：mvu.mjs 保持纯函数，不自己读 manifest。
   - 宿主启动时从 REG 里带 `viewer3d` 的图预取各 manifest（只取 `id`、`hotspots[].id/name`），组成 `partIndex = { 'dairy:tank': { zh, en, place: '奶牛场', map } }`。
   - 作为参数传给 `summarizeCustom / wbContent / findKey / normTarget`。
   - 取不到时降级：标准名 = 热点 id，省略 place。单元测试覆盖降级。
2. **提示词里的写法**：
   - `summarizeCustom` 和 `wbContent` 遇到 `part` 类时，把键渲染成「标准中文名」，并加上所在地点作前缀，例如 `奶牛场·奶罐与制冷→老白（每晚 10 点前要降到 4 °C）`。
   - 模型永远看不到 `dairy:tank` 这种写法。
   - 剧情标签 `⌖改名 奶罐与制冷 → 老白` 用标准中文名匹配（`findKey` 增加「part 的中文名 → id」映射），也认 `⌖改名 奶罐 → 老白` 这种中文名前缀。
3. **查看器读数据**：宿主向 iframe 发 `v3d:custom {prop, items: {tank: {名, 用途, 源, 待定?}}}`（全量，只含这个 prop）。
   - **时机**：收到 `estate:ready` 后必发一次（与 `v3dPending` 同一处），之后每次变更再发；iframe 重建（切图回来）同样由 ready 触发。
   - 收到第一条 `v3d:custom` 前按标准名渲染，收到后只替换文字，不闪烁。
   - **信息卡**：标题用你的叫法，旁边小字写标准名；多一行「用途」；显示徽章。
   - **部件列表**（右侧「部件」）：显示你的叫法，旁边小字写标准名。
   - **流程步骤条**：每步上行写你的叫法，下行小字写标准名；未改名的只写标准名一行。
   - **热点标记**：数字不变。
4. **查看器发编辑请求**：信息卡的「✎ 自定义」发 `v3d:edit {hotspot}`，由宿主打开同一个编辑抽屉。
   - 宿主必须校验 `ev.source === est.frame.contentWindow`，并且 hotspot 在 partIndex 里，否则忽略（与 `estate:ready` 的来源校验一致）。
   - 查看器里不做表单。好处是只有一处实现，主题和语言也都由宿主统一处理。
   - 抽屉盖在 iframe 上，≤ 640 px 时是底部抽屉。
5. **`EdenMap.flyTo` 的三种写法**：
   - `EdenMap.flyTo('dairy:tank')`（字符串）；
   - `EdenMap.flyTo({ part: 'dairy:tank' })`；
   - 旧写法 `{ map, hotspot }` 仍然有效。
   - 解析顺序：① 含 `:` 且前缀是 partIndex 里的 prop → 部件；② 否则在所有对象里精确匹配：键 / 标准名 > 你的叫法 > 部件标准中文名 > 旧叫法；③ 同一级命中多个 → 返回 `false`，不猜。map 由 partIndex 的 `map` 字段给出。
   - 找不到时返回 `false`，不弹错误。
6. **流程模式**：步骤的数据结构 `flow.steps[].hotspot` 引用同一个 id。步骤标题的取值优先级：你的叫法 > 步骤自己的 `label` > 热点标准名。CIP 这类不对应热点的步骤不能自定义，不显示 ✎。

## 5 来源、冲突与历史

- **冲突规则**：剧情标签要改的项如果 `源 === '手动'`，**不直接应用**，改为写入 `待定: [{op, value, floor}]`（每项最多 3 条，新的覆盖旧的）。
  - **待确认期间模型继续看到你的名字**，并在注入摘要该项后加 `（剧情里也叫观星台）`，避免后续楼层两个名字对不上。冲突框里写明「在你决定前，模型看到：星图室（剧情里也叫观星台）」。
  - toast「剧情想把「星图室」改成「观星台」· 查看」**每个聊天每次加载只弹一次**，之后只在悬浮按钮和「待确认 N」上显示角标。
  - 楼号可点：展开那一楼标签前后 60 字。
  - 卡片上出现「剧情标签待确认」徽章，并显示冲突框：「第 214 楼：⌖改名 书房 → 观星台」，按钮为「保留星图室」「用观星台」。
  - 选择接受后，旧名进入别名，`源` 改为 `标签`；选择保留则丢弃这条待定。
  - 没有手动设置过的项，剧情标签照旧直接应用。
  - **用途**的冲突同样处理。
- **例外开关**：全局「剧情标签可以直接改我起的名字」（默认关）；另有**单项开关**「这一项跟剧情走」（在抽屉里，写入 `跟剧情: true`），粒度更细。
- **历史**：每项记最近 8 条变更，格式为 `{名?, 用途?, 源, floor?, at}`，存在 `eden_map.自定义.items[k].史` 里。
  - 卡片编辑抽屉和管理中心里可以展开查看，默认只显示 2 条加「展开」；当前值用徽章「当前」，不是按钮。
  - 每条都有「恢复」按钮。
  - 标准名永远是最后一条，所以「恢复标准名」等于重置。
- **撤销**：保存、重置、接受剧情、删除这四个动作都有 10 s 的 toast「撤销」（时长可注入，便于测试），用单步快照实现。toast 消失后，历史最上面仍固定一条「刚才的改动 · 撤回」，直到下一次编辑。
  - 有了撤销，重置不再需要二次确认，删掉那个确认框。
  - 切换聊天时快照作废（快照按聊天存）；关闭面板不作废。
- **大小**：`史` 不进 `summarizeCustom` 和 `wbContent`，模型看不到历史。

## 6 发现性与引导

- **一次性提示**：第一次打开任意地点卡时，在「✎ 自定义」按钮下方弹出一个 accent 色小气泡：「任何卡片上的 ✎ 都能改叫法、写用途；模型会当作背景。」，右上角有 ×。
  - 关掉后，或者用户第一次保存自定义后，永久不再出现。
  - 状态按设备存本机，写在 `localStorage` 的 `edenMap:hint:custom`，读写都要包 try/catch。
  - 三维查看器第一次打开时同样出现一次，指向信息卡。
- **空状态**（管理中心）：
  - 一句话说明加上两个大按钮：「从地图上选」（关闭设置并高亮当前层的卡）和「搜索一个对象」（进入选择器）。
  - 下面放两个示例，其中一个用三维部件：「奶罐与制冷 → 老白」。
- **有自定义的对象**在地图标签上显示你的叫法，旁边用 `--fs-micro` 小字写标准名（见 `shots/card_*`）。缩放到很小时只显示你的叫法。

## 7 管理中心（设置页，简化）

示意见 `shots/hub_*`。

- **顶部**：标题「自定义」，旁边是计数和同步状态的一行小字，例如「5 项 · 世界书同步 开」。
- **筛选**：搜索框（常驻，不再是超过 5 项才出现），加上分段筛选：全部 / 地点 / 人物 / 三维部件 / **待确认 N**。
- **列表**：每行一项，显示你的叫法、标准名小字、用途摘要和来源。点整行打开同一个编辑抽屉。
  - 抽屉内有「在地图上看」和「重置」。「重置」放在抽屉底部的次要位置，因为已经可以撤销。
  - 列表行上不放 3 个按钮了，解决 A8。
- **「模型会看到」整体预览**：列表底部显示完整的 `summarizeCustom` 原文，默认折叠成 2 行。超过 220 字时标出截断点，并提示开启世界书同步。
- **同步设置**：挪进二级页「同步设置」，包括开关、存储位置和未绑定警告。主页面只留状态那一行小字。

## 8 手机、主题、语言、动效

- **尺寸**：所有可点目标 ≥ 44 × 44（`--hit`）；抽屉操作条贴底，并加 `env(safe-area-inset-bottom)`。
- **触屏焦点**：触屏上不自动聚焦输入框；抽屉打开后焦点落在标题。
- **三维查看器**：≤ 640 px 时信息卡是底部抽屉，流程步骤条移到顶部模式切换条下方，两者不重叠（`shots/v3d_m375_*`）。
- **颜色**：只用 `map/ui/tokens.css` 的语义令牌，组件 CSS 里不出现 `.light`。
  - 输入框背景用 `--bg`，文字用 `--ink`，并显式声明 `color-scheme`，防止回到「白底白字」。
  - 不再用原生 `<select>`，分段筛选用按钮组。
- **语言**：所有文案进入 i18n 键 `cu2.*`，每个键都给出中文和英文（示意 `?lang=en`，见 `card_*_dark_en.png`）。
  - 英文界面里，标准名照原样显示中文，因为它就是卡里的数据。
- **动效**：`prefers-reduced-motion` 时去掉标签脉冲、抽屉滑入和飞行动画（改为直接跳转）。

## 9 数据改动汇总（向后兼容）

```
eden_map.自定义 = {
  items: { [key]: { 类: 'room'|'area'|'landmark'|'character', 名?, 用途?, 别名?, 源?, 跟剧情?, 待定?: [{op,value,floor}], 史?: [{名?,用途?,源,floor?,at}] } },
  部件: { [prop]: { [hotspotId]: { 同上结构, 类: 'part' } } },
  同步世界书, 同步手动?, 剧情可覆盖?: false
}
```

- `normCustom` 要保留 `部件`、`待定`、`史`、`跟剧情` 这些新字段，并对它们裁剪上限。旧数据里没有这两个字段，读取时照常工作。
- 旧版本的 `normCustom` 会丢掉新字段：回退后三维自定义和历史会丢失，但模型不会看到 `dairy:` 这类键。发布说明写明。
