# 文案风格标准（COPY-1，2026-10-03）

> 状态：2026-10-03 起生效。给地图上所有用户可读文字定词；sweep 技能 §5b 的「Words」检查以本文为准，
> 机器门槛在 `tools/check_copy.py`（smoke 内跑）。盘点：`docs/copy-inventory.md`。中文为准，英文镜像。

## 1. 一句话标准

用户不看说明书就知道发生了什么、对自己意味着什么、要不要做什么——用酒馆玩家的词说，不用我们的词说。

## 3. 写作规则（逐条可查）

1. 说清楚三件事：发生了什么、对你意味着什么、要不要做什么（大多数时候是「什么都不用做」）。
2. 不出现内部词：模块名、键名（`edenMap*`）、构建编码（`S1-…`）、提交号、决策号（D/K-R）、`head #N`
   （例外：设置 › 关于与更新与版本，它就是版本号）、JIT、MVU、ledger、pack。
3. 不用 emoji 与装饰字形：✅ ⚠ ✓ ✗ ◆ ★ 箭头图标都不进文字；状态用文字与颜色，方向用「从…到…」
   或表意的 `A → B`。`×`（关闭）、`⋯`（更多）、`…`（省略）、`·`（间隔）可用。
4. 没有 AI 腔：不用「我们为您」「已为你」「一键」「轻松」；不用感叹号；不堆形容词；不写「不是…而是…」。
5. 短：toast 一行结论（≤ 24 字为宜），横幅最多两行正文；说明文字一两句，解释留在「了解更多」。
6. 一个事件只提示一次：同一动作不叠两条 toast；同一版本同一组警告只弹一次（已有机制）。
7. 同一处地方式命名一个东西：词条名、按钮字、标题互相一致（例：设置里叫「迷雾探索」，开关就叫「迷雾探索」）。
8. 报错可行动：错误提示带下一步（重试 / 检查网络 / 到哪里设置），不甩错误码；错误码和堆栈进反馈报告（诊断文本）。
9. 更新提示（更新后第一条）：标题 = 版本号；正文 = 一两行「这次改了什么」（发版时写进 `map/data/build.json`
   的 `notes` 数组，1–3 行短句，`tools/version_code.py` 会保留）+「怎么更新」一行；构建编码不上屏。
10. 世界书同步提示：说哪本书、新增 / 更新了几条、你改过的几条保留原样；不说版本号跳变，不教用户去哪关（设置里本来就有）。

## 4. 调试视图的豁免

反馈报告（`app/feedback-report.mjs`）、设置 › 开发者、`版本编码，点击复制` 属诊断面：技术词、版本编码、
状态记号只在这里出现，不出现在 toast、横幅、卡片、说明文字里。
